# Authored index coverage (public #384)

Bounded model of index-keyed authored-write coverage across checkpoint restore,
WAL replay and crash-reopen. `AuthoredIndexCoverage.tla` explores the
interleavings of registration, honest commits, an `Unavailable` packet, one
legacy `Complete` packet, one adversarial `Covered` packet with a wrong bound,
checkpoints and reopens. Recovery is modelled as paired views over one history:
view `k` certifies commits `1..k` from the checkpoint at the receiving catalog
and replays commits `k+1..n` from the WAL tail. The Rust mirrors are listed in
the module header. The Lean development in
[`specs/lean/authored_index_coverage`](../../lean/authored_index_coverage/README.md)
proves the same properties unbounded.

## Invariants

- `CoverageSound`: coverage never extends an index introduced at or after the
  commit's bound, and an admitted span holds every write of that index.
- `UnprovenancedRefuses`: unavailable, legacy and adversarial packets mint
  nothing, and every span over them refuses.
- `RecoveryParity`: every split between checkpoint and WAL tail mints and
  admits identically to WAL-only replay.

## Run

```
python tools/tla/run_tlc.py specs/tla/authored_index_coverage/AuthoredIndexCoverage.tla
```

Expected: `Model checking completed. No error has been found.` (285,612
distinct states with `MaxDefs = 3`, `MaxCommits = 4`, `MaxReopens = 2`; about
3 minutes on 4 workers).

## Negative controls

Each mutant module sets `Mutant` and checks the invariant it must break.

| Module | Mutant | Expected |
|---|---|---|
| `AuthoredIndexCoverageMutantCertifyNext` | certify mints from the reopen-time next id, not the bound | `CoverageSound` violated |
| `AuthoredIndexCoverageMutantLegacyW` | certify accepts a legacy packet with the delta's next id | `UnprovenancedRefuses` violated |
| `AuthoredIndexCoverageMutantLegacyWSafety` | the same mutant, checked only for soundness | no error: an honest legacy bound is sound, so the refusal is a provenance rule, not a soundness patch |
| `AuthoredIndexCoverageMutantRemint` | WAL replay re-mints a legacy packet | `RecoveryParity` violated |
| `AuthoredIndexCoverageMutantOutOfOrder` | the checkpoint catalog readmits definitions in reverse order | `CoverageSound` violated |

```
python tools/tla/run_tlc.py specs/tla/authored_index_coverage/AuthoredIndexCoverageMutantCertifyNext.tla
```

## Trace validation

`AuthoredIndexCoverageTrace.tla` replays NDJSON traces written by the relational
courts in
`crates/worth-court-relational-certification/.../authored_write_history/indexed/durable_coverage.rs`
(writer: `durable_coverage/trace.rs`). Set `WORTH_DST_TRACE_DIR` when running
them:

```
WORTH_DST_TRACE_DIR=<dir> cargo nextest run --profile integration \
  -p worth-court-relational-certification -E 'test(/durable_coverage/)'
python tools/tla/run_tlc.py trace \
  specs/tla/authored_index_coverage/AuthoredIndexCoverageTrace.tla <dir>/<trace>.ndjson
```

Each packet kind and bound is read from the durable artifact bytes, and the
trace spec requires a `Covered` bound to equal the catalog's next id at that
commit. Certification is internal to the catalog owner, so it is observed
through what it decides: `Admit` records carry the recovered cursor's actual
answer and `Postings` records the actual scan. A trace passes only if every
record is a step or observation the model allows (`TraceAccepted`); a trace
whose observation disagrees with the model stops early (TLC reports a
deadlock).

The traces in `traces/` were generated by those courts:

| Trace | Recovery |
|---|---|
| `authored-index-coverage-all-checkpoint.ndjson` | checkpoint of every commit, empty tail |
| `authored-index-coverage-wal-only.ndjson` | WAL replay only |
| `authored-index-coverage-mid-checkpoint-and-tail.ndjson` | checkpoint mid-span plus a WAL tail |
| `authored-index-coverage-legacy-wal-tail.ndjson` | a legacy packet in the WAL tail |
| `authored-index-coverage-legacy-checkpoint.ndjson` | the same legacy packet restored from a checkpoint |
