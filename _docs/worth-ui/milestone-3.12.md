## Goal and Central Claim

Worth UI may change mounted truth only through this compiler-visible
progression:

```text
source-specific validated evidence
-> UiAdmittedObservation
-> non-empty UiAdmittedObservationSet
-> UiChangeClassificationOutcome
   -> UiObservedNoChangeReceipt                 (terminal)
   OR UiEvidenceOnlySourceChange               (preservation-only plan)
   OR UiClassifiedChange
      -> UiResolvedAffectedScope
-> immutable UiRebindPlan
-> move-only UiPreparedRebind
-> canonical host presentation
-> atomic successor publication
-> UiRebindOutcome
```

For a file-authored attempt, the source-specific prefix is:

```text
operating-system watcher hint
-> exact settled source snapshot and revision
-> one worth-ui-dsl compile
-> WorthUiDslCompileReport
   OR sealed semantic package plus package-bound lowering/provenance evidence
-> exact-basis source candidate
-> source semantic admission
```

The watcher is transport. Source settlement owns the frozen revision.
Transport reports only what bears on the source tree: creation, content or
structure modification, rename, and removal. Access notifications (opens and
closes, which inotify emits for every file the watcher or compiler itself
reads) are dropped at ingress and never become a source hint, because a
hint that fires on reading would settle a revision that nothing edited.
`worth-ui-dsl` owns parsing, legality, normalization, lowering, compile
diagnostics, authored spans, and package provenance. Declaration contracts own
semantic fact and aspect meaning. Runtime observation and rebind owners own
classification, affected scope, execution, and publication.

A raw watcher event, source path, validated mechanical host report,
measurement payload, Query patch, service callback, graph node, mounted
receipt, pixel, screenshot diff, diagnostic reference, digest, or printable
identity cannot skip a stage or construct later authority.

The milestone is complete only when:

- one bounded external edit visibly changes the permanent Platform Pulse
  through the real watcher without restarting the process;
- one unaffected visible control remains stable where the plan admits
  preservation;
- one malformed edit preserves the last admitted page and returns its exact
  typed DSL failure without inventing later-stage identity;
- recovery succeeds in the same process;
- predecessor and successor visual snapshots can be compared through a
  separate derived inspection capability; and
- unchanged ordinary frames perform no observation, rebind, comparison, or
  pixel work.

Those proof producers do not yet compile into one runtime-owned answer to:


Programmatic broad replacement remains lawful only by lowering into that same

## Governing Design

### 1. Source Attempt and Observation Admission

#### Authored source bridge

The ordinary watched edit crosses these owners exactly once:

```text
watcher
  emits a mechanical hint

source settlement
  freezes one exact source-package revision

runtime/source_ingress/source_rebind_attempt
  consumes that settled snapshot once
  invokes worth-ui-dsl once
  binds either outcome to revision, ordering, counters, and capability basis

worth-ui-dsl
  -> exact typed compile report
     OR sealed semantic package plus lowering/provenance evidence

source replacement proof
  binds candidate to revision and active basis
  compares canonical declaration meaning

runtime observation/rebind
  admits facts, resolves scope, plans, effects, and publishes
```

`worth-ui` curates the move-only request but owns no DSL branch. General
observation and rebind owners never accept source bytes, settled snapshots, or
compiler inputs. A compile failure stops in the attempt owner and becomes a
`UiSourceCompilationDenialReceipt`; it cannot expose a later-stage identity.

Source evidence and semantic identity remain distinct. An edit that changes
only governed spans/provenance becomes evidence-only succession. An edit that
changes executable meaning produces declared semantic facts even when pixels
happen to remain equal.

#### Observation families

Each family has its own evidence type, owner, ordering/loss policy, and
admission method:

| Family | Admitted evidence | 3.12 posture |
| --- | --- | --- |
| Authored source | Exact-basis sealed source candidate | Fully admitted |
| Host viewport/device scale | `UiValidatedHostObservationBatch` | Admitted as `UiHostObservation` |
| Other host families | Validated mechanical reports | Typed owner-unavailable; intent/services own later admission |
| Measurement | Solicited exact request/result basis | Fully admitted |
| Query | `WorthUiCollectionChangeConsequence` through framework-turn capability | Fully admitted without raw Query artifacts |
| Existing runtime sources | Committed scroll-extent and portal-anchor consequences | Fully admitted |
| Future intent/services | Owner-specific request or committed state | Cannot enter the rebind observation set in 3.12 |

The host adapter drains bounded mechanical reports after host calls through the
existing non-reentrant boundary. It never classifies UI meaning.

`UiObservationFamilyDefinition` declaratively binds an owner to:

- admitted evidence and runtime-state access;
- produced fact contract;
- ordering, duplicate, loss, reset, coalescing, and conflict semantics;
- comparison and byte-cost rules; and
- future insertion identity.

The sealed framework definition set drives exhaustive admission,
classification, ordering, inspection, and certification. Adding a family must
break those sites until handled.

`UiAdmittedObservation` proves one owner-specific item is valid against the
active session and exact source basis. It authorizes only inclusion in its
observation turn.

`UiAdmittedObservationSet` is created only by consuming a non-empty,
canonically ordered same-turn set. An empty turn, duplicate, historical,
unavailable, or rejected admission remains a typed terminal posture, not a
fake set member. Rejection poisons an atomic turn; unavailable optional
families do not, unless the turn declared them required.

Cross-family ordering uses framework rank plus owner-issued ordering keys. It
does not claim a global physical timestamp. Duplicates and owner-proven
equivalent entries may coalesce only under the family contract.

### 2. Classification, Affected Scope, and Planning

Classification of a non-empty admitted set returns:

```rust
pub enum UiChangeClassificationOutcome {
    ObservedNoChange(UiObservedNoChangeReceipt),
    EvidenceOnly(UiEvidenceOnlySourceChange),
    Changed(UiClassifiedChange),
}
```

`ObservedNoChange` is terminal and performs no planning or presentation.

`UiEvidenceOnlySourceChange` carries the exact candidate,
predecessor/successor source bases, package-bound provenance delta, and source-
equivalence proof. It authorizes only a preservation plan with structurally
empty changed-fact, affected-aspect, consumer, invalidation, remount, binding,
and allocation collections. That plan advances authored-generation truth and
publishes a fresh frame while preserving instances and incarnations.

`UiClassifiedChange` contains only facts permitted by each owner's sealed
`UiProducedFactContract`. Reset meaning is an explicit owner-issued fact, not
an inference from missing increments.

Produced and consumed fact contracts are distinct types:

```text
owner-issued changed fact constrained by UiProducedFactContract
INTERSECT
declaration/subsystem UiConsumedFactContract
-> exact affected consumer candidates
```

The canonical scope derivation is:

```text
changed facts
-> declaration-owned fact-to-aspect consequences
-> affected aspects
-> consumed-fact and consumed-aspect index lookup
-> deduplicated UiResolvedAffectedScope
```

Watcher hints, source spans, classifier convenience, and host adapters cannot
invent or widen consequences. Unknown selectors, missing index truth,
incompatible generations, or exhausted lookup budgets deny before effects.
There is no whole-graph fallback.

`UiGraphConsumedFactIndex` and `UiGraphConsumedAspectIndex` are disposable,
graph-basis-bound projections. Authoritative declarations and subsystem
contracts remain truth. Destroying and rebuilding both indexes must reproduce
canonical entries and the same affected scope from the same authoritative
basis without source reread or global scan. Basis drift discards the rebuilt
candidate rather than partially patching current truth.

#### Identity and lifecycle decisions

| Change posture | Application generation | Instance/incarnation | Other consequence |
| --- | --- | --- | --- |
| Duplicate or same semantic value | Preserve | Preserve | No new frame receipt |
| Evidence-only source | Advance | Preserve both | Fresh frame and authored provenance |
| Appearance/content | Advance | Preserve unless owner proof says otherwise | Re-present selected visible scope |
| Layout/viewport/measurement | Source-dependent | Preserve unless remount selected | Recompute indexed allocation neighborhoods |
| Query incremental/reset | Preserve unless source replacement | Only owner-authorized graph consequences | Preserve, rebind, reset, or retire exact binding scope |
| Local structure edit | Advance | Preserve unaffected; fresh incarnation only on actual remount/create | Exact create/drop/move/rebind sets |
| Broad/reset replacement | Advance when source changes | Explicit plan | Every selected entry remains counted |

Mounted receipt identity is frame-scoped. Mounted instance identity and mount
incarnation are distinct; an actual remount always creates a fresh
incarnation. Pixel and snapshot identities never substitute for semantic or
mounted identity.

#### Immutable plan

Only `UiResolvedAffectedScope` or
`UiEvidenceOnlySourceChange::compile_preservation_rebind` can construct
`UiRebindPlan`. The plan fixes:

- observation and predecessor/candidate bases;
- semantic posture and owner proofs;
- changed facts, affected aspects, lookup receipts, and selected consumers;
- preservation, graph, mount, measurement, allocation, binding, obligation,
  surface, and retirement subplans;
- declarative effect, read/write/invalidation/conflict, and parallel-admission
  sets;
- host capability and presentation basis;
- deadline, cancellation, retry, idempotency, artifact, disclosure, and safe-
  point policy;
- structural estimates and budget; and
- currentness checks and integrity.

Existing replacement, Query succession, viewport, scroll, portal,
measurement, and allocation proof enters as immutable subplans. The executor
does not repeat comparison, identity matching, classification, affected-scope
discovery, preservation, Query succession, or obligation selection.

### 3. Effects, Publication, and Recovery

Final current-basis admission consumes a lawful plan and produces move-only
`UiPreparedRebind`. All fallible graph, mount, allocation, binding, obligation,
surface, presentation, retention, and failure-artifact preparation occurs
before the first host effect.

`UiRebindEffectSet` is the only executor input describing mutations. The
executor may sequence or parallelize only effects admitted by the plan's
conflict proof. It cannot amend the effect set or discover new consumers.

Presentation uses the inherited canonical host contract. Complete
presentation feeds the existing allocation-free atomic publication of the
current application, graph, plan, allocation, mounted frame, and inspection
truth. There is no rebind-specific publication path.

```rust
pub enum UiRebindOutcome {
    Duplicate(UiDuplicateObservationReceipt),
    ObservedNoChange(UiObservedNoChangeReceipt),
    RejectedBeforeEffects(UiRebindDenialReceipt),
    CancelledBeforeEffects(UiRebindCancellationReceipt),
    TimedOutBeforeEffects(UiRebindTimeoutReceipt),
    SupersededBeforeEffects(UiRebindSupersededReceipt),
    Published(UiRebindReceipt),
    InFlight(UiRebindCompletionHandle),
    Indeterminate(UiRebindRecoveryHandle),
    InternalDefect(UiRebindInternalDefectOutcome),
}
```

Only `Published` carries `UiRebindReceipt`. It proves complete presentation,
atomic publication, exact predecessor/successor identities, planned and
realized consequences, structural/physical cost, disclosure/retention
posture, and zero outstanding recovery authority. A planned/realized mismatch
is an internal defect, not advisory success.

The receipt disposition is either `Complete` or
`CompleteWithAdvisories(UiRebindAdvisorySummary)`. Advisories are typed,
non-authoritative evidence and cannot change correctness or excuse a
planned/realized mismatch.

All denials preserve an exact stopped phase and valid next action. Source
compilation denial retains the DSL report but no later identities.
Cancellation never claims rollback. A pre-effect internal defect preserves the
predecessor and carries no recovery authority. A defect or uncertainty after
any native effect becomes `InFlight`, `Indeterminate`, or an after-effects
internal-defect outcome with registered recovery authority.

Completion, retry, and recovery handles are runtime-owned, bounded,
enumerable, and disposable. Retry exists only through a handle that preserves
an exact pre-effect basis. Callers never receive a raw executable plan.
Indeterminate outcomes preserve separate runtime-current truth and known host-
presentation truth and reuse the Milestone 3.10 reconciliation owner.

Every admission, planning, execution, publication, comparison, completion, and
recovery outcome derives its semantically named boundary core from exact
session/source basis, stopped phase, effect count, commit posture, valid next
action, disclosure, and cost. This shared projection does not become a
universal runtime event or interchangeable authority type.

Observation/rebind runtime state is required in every active application
session, successor/fork, replacement, and shutdown path. It has no optional or
lazy production construction. Shutdown closes admission, disposes queued and
pre-effect work, resolves or transfers effecting work, and leaves zero
registered resources.

### 4. Evidence, Comparison, and Compatibility

Runtime terminal receipts are authoritative evidence of what occurred.
`worth-ui-inspection` owns immutable audience projections only. It cannot
construct runtime identity, facts, plans, retries, or recovery.

Milestone 3.12 maintains bounded exact-key evidence references for:

- source-rebind attempts and exact authored generation/spans;
- package provenance and declaration change;
- changed facts and affected scope;
- reached, omitted, expired, or deferred stop points;
- rebind decisions and denials; and
- structural cost.

Summary and reference lookup are available in 3.12. Materialized causal
diagnostics remain 3.19, replay remains 3.21, and the inspector remains 3.22.
Those products consume this substrate without entering the ordinary lane or
gaining reverse authority.

Bounded `UiRebindDecisionRecord` lookup is derived from retained terminal
receipts. Destroying its index may make lookup unavailable, but reconstruction
cannot execute, retry, amend, or republish a rebind.

#### Identity-aware visual comparison

Comparison is requested derived work:

```text
borrowed predecessor UiVisualSnapshotReceipt
+ borrowed successor UiVisualSnapshotReceipt
+ borrowed published UiRebindReceipt
+ UiVisualSnapshotComparisonRequest
+ concrete UiVisualSnapshotComparisonGrant
-> UiVisualSnapshotComparisonOutcome
```

```rust
let grant = shell
    .visual_inspection_authority()
    .issue_comparison_grant();
let request = UiVisualSnapshotComparisonRequest::between(
    &predecessor_snapshot,
    &successor_snapshot,
    &rebind_receipt,
)
.with_pixel_observation(UiVisualComparisonPixelPolicy::IfAlreadyRetained)
.with_budget(UiVisualSnapshotComparisonBudget::bounded(128)?);

let comparison = shell.compare_visual_snapshots(&grant, request);
```

The synchronous request borrows all receipts. It neither consumes nor clones
their registered resources. The caller disposes both snapshots independently
after projecting required protocol evidence.

The comparison grant is concrete, session/audience/disclosure-bound, and not
substitutable with capture, geometry, pixel, or overlay grants. Comparison may
report instance/incarnation continuity, created/retired/rebound/remounted/moved
regions, affected/unaffected visible regions, optional already-retained pixel
observations, and structural cost.

Its outcome is `Compared`, `Omitted`, `Expired`, `Incompatible`, or `Denied`.
Budget denial carries exact counters and retains no background job. Comparison
cannot authorize or amend a plan, infer identity from pixels, recapture an
expired predecessor, or decide semantic preservation.

The Platform Pulse retains the predecessor in an
`AwaitingRebindComparison` product state, captures the successor after valid
publication, compares, publishes the v3 observation, and then disposes both.
Malformed edits do not fabricate a successor or comparison. Partial failure
and shutdown dispose whichever snapshots exist.

#### Protocol, disclosure, and retention

Process-local observation, plan, and prepared types are not wire formats.
Process-crossing evidence uses stable protocol identity and version.

Milestone 3.12 advances
`worth-ui.platform-pulse.lifecycle-observation` from `v2` to `v3`.
Rebind and visual comparison are typed v3 families, not competing protocols.
The v3 producer never down-converts to v2.

The v3 decoder accepts:

- v3 as complete 3.12 evidence; and
- governed raw v2 fixtures only as typed `InheritedLifecycleOnly` evidence.

V2 cannot synthesize rebind/comparison fields or close the 3.12 courtroom.
Closed 3.11 failure bundles use the separate
`worth-ui.platform-pulse.failure-artifact.v1` manifest and normalized traces;
they are not raw v2 envelopes and must not be relabeled or given invented
fields. Phase 1 inventories both artifact classes.

Milestone 3.13 may retire v2 decoding only after governed raw v2 evidence has
expired, migrated without invented meaning, or been deleted under policy.
Unknown identities and versions fail before interpretation.

Plans, receipts, source spans, Query evidence, comparisons, pixels, and
failure bundles retain explicit audience, disclosure, retention, deletion,
legal-hold, and shutdown posture. Diagnostic sidecars cannot change canonical
correctness meaning.

### 5. Cost, Capacity, and Concurrency

Source settlement and full-file DSL compilation are an explicit source-edit
cost lane. Milestone 3.12 does not claim incremental parsing or module
compilation before 3.18.

After classification, semantic rebind work is bounded by:

```text
O + F + A + C + R + G + M + B
```

where the axes are admitted observations, changed facts, affected aspects,
indexed consumers, selected decisions, graph/index entries,
measurement/allocation entries, and binding transitions. Work may not scale
with unrelated graph width, Query width, pixels, or inspectors. A broad plan
is lawful only when every selected entry is counted.

Physical work is reported separately:

```text
ordinary presentation: S + P + N
completion lane:       Xc
recovery lane:         Xr
```

`S`, `P`, and `N` are affected surfaces, prepared/presented bytes, and native
calls/submissions. Completion and recovery work never amortize into the
ordinary successful lane. Requested comparison and causal inspection have
separate budgets and cost receipts.

Every ordinary, completion, and recovery hot path registers its lane, formula,
input axes, counter source, and proof in the workspace complexity contracts.
The 3.12 paths may not ship as undocumented performance debt.

The Platform Pulse profile is fixed:

| Axis | Limit |
| --- | ---: |
| admitted observations per turn | 8 |
| retained observation bytes per turn | 65,536 |
| queued observations during one effecting rebind | 16 |
| changed facts / affected aspects | 16 / 16 |
| distinct indexed consumers | 64 |

| Query binding transitions | 16 |

Changing a limit requires a profile-identity and specification revision.
Existing 3.11 visual budgets remain independently binding.

Application construction is compiler-checked:

```rust
let change_profile = UiChangeProfile::new(
    UiObservationProfile::bounded(observation_budget, observation_queue)?,
    UiRebindProfile::bounded(rebind_budget, rebind_concurrency)?,
);

let app = WorthUi::app()
    .with_change_profile(change_profile)
    .freeze()?;
```

The subsystem profile values are validated typed groups, not positional raw
integers. Invalid profiles return `UiChangeProfileConstructionDenial`; they do
not clamp or default. A production builder without a complete profile cannot
freeze. Certification may use named smaller profiles through the same
constructors.

Ordinary unchanged frames allocate and execute nothing for observation,
classification, rebind, comparison, or pixels. Admission rejects cheapest
owner/basis failures before retained allocation. Plans, prepared state,
queues, receipts, handles, and comparison inputs have one runtime owner and
exact terminal accounting.

At most one Platform Pulse rebind effects at a time. Later observations enter
the bounded runtime queue; only owner-proven equivalents coalesce. Exhaustion
returns typed backpressure or overflow and never widens scope or starts
unbounded background work.

Cancellation safe points are fixed at pre-classification,
post-classification, post-scope, post-plan, post-reservation, final current-
basis admission, and pre-first-host-effect. There is no hidden cancellation
inside atomic publication. Deadlines use the typed session monotonic-clock
basis, never wall-clock ordering.

## Public Developer Experience

The ordinary shell owns the host adapter and execution substrate. The caller
provides only policy it honestly owns:

```rust
let request = UiSourceRebindRequest::new(settled_snapshot)
    .with_deadline(deadline)
    .with_cancellation(cancellation)
    .with_idempotency(UiRebindIdempotency::SourceEvidence)
    .with_retry_tolerance(UiRebindRetryTolerance::PreEffectOnly)
    .with_artifact_policy(UiRebindArtifactPolicy::Ordinary);

match shell.begin_source_rebind(request)? {
    UiRebindOutcome::Published(receipt) => inspect(receipt),
    UiRebindOutcome::RejectedBeforeEffects(denial) => {
        assert!(denial.predecessor_remains_current());
        report(denial.stage(), denial.valid_next_action());
    }
    UiRebindOutcome::InFlight(handle) => manage(handle),
    UiRebindOutcome::Indeterminate(recovery) => reconcile(recovery),
    outcome => record(outcome),
}
```

`begin_source_rebind` names the mutation/effect boundary. No
observation-named getter may hide planning or presentation. Public execution
accepts no host adapter, executor, scheduler, mutable runtime state, raw
identity, free-form idempotency key, or authority marker.

Advanced callers with active-session authority may explicitly admit
source-family evidence, seal the turn, classify, resolve scope, compile the
plan, inspect it immutably, and begin rebind. Valid next methods arise from the
current proof type; no raw or earlier-stage value exposes execution.

The governing public roots are:

- `UiChangeProfile`, `UiObservationProfile`, and `UiRebindProfile`;
- `UiAdmittedObservation` and `UiAdmittedObservationSet`;
- `UiChangeClassificationOutcome`, `UiEvidenceOnlySourceChange`,
  `UiClassifiedChange`, and `UiResolvedAffectedScope`;
- `UiRebindPlan`, `UiPreparedRebind`, and `UiRebindOutcome`;
- `UiSourceRebindRequest`, `UiRebindExecutionRequest`, and
  `UiRebindReceipt`;
- managed completion, retry, and recovery handles;
- exact-generation rebind inspection references; and
- the visual comparison grant, request, budget, outcome, and receipt.

The representations and subordinate private type names remain implementation
choices unless this specification gives them authority-distinct meaning.

## Architectural Destination

### Crate Responsibilities

- `worth-ui-dsl` owns source language meaning, sealed packages, compile
  reports, spans, and provenance. It imports no runtime, graph, host, Query, or
  rebind authority.
- `worth-ui-host-contract` owns raw mechanical reports and the bounded
  non-reentrant drain contract.
- `worth-ui-host-egui` translates egui mechanics and performs canonical
  presentation. It owns no semantic classification.
- `worth-ui-query-binding` remains the only production Query importer and
  produces UI-owned consequences.
- `worth-ui-runtime` owns source-attempt orchestration, semantic admission,
  classification, affected scope, planning, preparation, execution,
  publication, decision evidence, and managed lifecycle.
- `worth-ui-inspection` owns immutable rebind/comparison evidence contracts and
  bounded projections without runtime construction authority.
- `worth-ui` curates ordinary and advanced facades and owns no duplicate DSL,
  invalidation, execution, or publication truth.
- Platform Pulse owns product composition and process-crossing projection.
- `worth-ui-certification` owns hostile worlds and independent adjudication,
  never production authority.

### Structural and Dependency Enforcement

The stable axes are:

- `fact_contract/`: authoritative produced/consumed meaning, never execution;
- `runtime/observation/`: admitted state evidence, never intent, services, or
  effects;
- `runtime/rebind/scope/`: exact intersection, never source mechanics;
- `runtime/rebind/planning/`: immutable decisions, never mutation;
- `runtime/rebind/execution/`: effects and publication, never
  reclassification;
- `inspection/`: bounded derived evidence, never operational authority; and
- host adapter paths: mechanical translation/presentation, never UI semantics.

Boundary and agent-context enforcement must prove:

- tier direction and existing Query/replay restrictions remain green;
- only owners construct produced facts and governed phase proofs;
- source candidates retain exact snapshot/DSL/package/capability affinity;
- runtime observation/rebind cannot import source bytes or compiler input;
- host and inspection crates cannot import runtime execution;
- `worth-ui-query-binding` remains the only Query importer;
- public execution accepts no host/executor mechanism;
- ordinary and broad replacement share one executor/publication route;
- future intent/services cannot enter the rebind observation set;
- derived indexes rebuild without changing authority;
- no test-only product branch, new integration target, nested Cargo build, or
  line-cap exemption appears; and
- deleting or bypassing the canonical route turns topology/proof evidence red.

The tree forbids catch-all event, observation-manager, rebind-helper, and
change-utility modules; planning inside the Platform Pulse or host adapter;
Query translation inside runtime rebind; comparison inside the planner; and
certification mutation hooks in production.

## Ordered Phases

### Phase 1: Contract, Cutover, and Topology Freeze

Make the migration mechanically explicit before semantic implementation.

Required:

- inventory every current source replacement, host observation, measurement,
  Query consequence, viewport, scroll, portal, invalidation, publication, and
  comparison route;
- classify each route as retained proof producer, canonical cutover, typed
  unavailable family, committed successor, or deleted predecessor;
- freeze public authority progression, outcome topology, family ownership,
  source/ordering rules, exact profiles, protocol coexistence, inspection
  support, and the destination tree;
- create the open Phase 5 manifest/ledger skeleton and independent change/order
  model vocabularies;
- inventory raw v2 envelopes separately from failure-artifact traces; and
- establish dependency and compile-contract baselines plus opening costs.

After Phase 1, an unadjudicated mutation route, generic event bag, optional
runtime subsystem, hidden executor facade, or topology that forces 3.13–3.15
to move the rebind boundary is forbidden.

Phase 2 may trust ownership and topology, not semantic admission.

### Phase 2: Source-Specific Semantic Observation Admission

Make every planner input canonical, owner-issued, and effect-free.

Required:

- implement required observation runtime state, exact turns, family
  definitions, admission outcomes, canonical ordering, and summaries;
- cut the settled-snapshot DSL invocation into the runtime source-attempt
  owner and produce either exact compile denial or a sealed candidate;
- preserve package-bound provenance through successful source admission;
- admit viewport/device scale, solicited measurement, Query consequence, and
  committed runtime-state sources through their distinct methods;
- return typed unavailable outcomes for successor-owned host families;
- add bounded host-report drain through adapter-owned retention and the
  existing raw validation boundary; and
- prove admission performs no scheduling, mutation, or host effect.

Raw or merely validated inputs cannot classify or execute. Query consequences
cannot escape their UI translation. Source-family ordering cannot become
cross-source wall-clock ordering.

Phase 3 may trust a non-empty set of canonical semantic evidence bound to one
turn.

### Phase 3: Changed Facts, Affected Scope, and Immutable Planning

Build the complete semantic compiler before effects.

Required:

- implement produced/consumed fact contracts and disposable graph indexes;
- classify no-change, evidence-only, changed, and explicit reset postures;
- derive declaration-owned aspects and indexed consumer scope;
- compile exact preservation, graph, mount, measurement, allocation, binding,
  obligation, surface, and retirement decisions;
- compile declarative effects, conflict footprint, and parallel admission;
- consume caller execution policy into an immutable exact-basis plan;
- enforce configured pre-effect budgets and currentness;
- prove change/identity behavior against the independent model; and
- prove post-classification slope independent of unrelated graph width.

No index miss may scan globally. The executor cannot rediscover scope.
Preserve/remount cannot collapse to booleans, heuristics, pixels, or position.

Phase 4 may trust one complete immutable decision artifact.

### Phase 4: Execution, Receipt, Comparison, and Platform Pulse

Carry the plan through the real effect boundary and permanent product.

Required:

- implement required rebind runtime state, final admission, preparation,
  effect sequencing, completion, recovery, and shutdown;
- prepare every fallible input before effects and publish only through the
  inherited atomic boundary;
- implement the full typed outcome topology and managed handles;
- project bounded decision/source/fact/stop-point evidence;
- implement comparison grant/request/outcome and snapshot retention lifecycle;
- cut the native shell and watcher to observation/rebind;
- emit v3, dual-read governed v2 as inherited-only evidence, and preserve the
  separate failure-artifact contract;
- close valid edit, malformed preservation, recovery, comparison, and teardown
  in the same Platform Pulse process.

Direct watcher publication, execution without a prepared plan, comparison-
driven preservation, premature snapshot disposal, and unowned post-effect
state are forbidden.

Phase 5 may trust the complete product path and attack recurrence, cost, and
closure.

### Phase 5: Torture Closure, DX, Documentation, and Deletion

Close every proof and remove every competing route.

Required:

- close `RB-01` and `TT-01` through `TT-12` with independent oracles, named
  mutations, structural cost, and teardown evidence;
- self-audit the Phase 5 manifest/ledger and prohibit closure with any open or
  fabricated row;
- prove capacity, concurrency, cancellation, timeout, supersession,
  uncertainty, recovery, index reconstruction, snapshot expiry, and shutdown;
- run the nonshipping family-insertion mutation;
- expose and compile the ordinary/advanced public examples;
- create or revise the continuing documentation below;
- delete or contain every predecessor execution/publication route;
- capture comparable closing build/test/runtime costs; and
- run formatting, clippy, workspace tests, line cap, dependency,
  boundary-check, agent-context, compile-contract, application-contract, and
  Windows executable-world gates against final source.

The milestone is not closed while an old ordinary mutation path survives, a
ledger row is open or non-causal, source compilation is mislabeled rebind
cost, derived inspection taxes unchanged frames, a governed resource leaks, or
3.13–3.15 require boundary relocation.
