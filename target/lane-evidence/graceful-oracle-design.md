# H3 graceful owner oracle design

Authority: milestone-3 Delivery tracks H3, D14 and D18. This is the M2 relational_home prefix/reopen pattern at the public application Home boundary, not its C4 media campaign. Subjects now are Relational graph/identities and World heads, occurrences/ancestry and custody. Signal and changed-build dimensions remain H5/H6 extensions.

Generator: every u64 seed yields twelve bounded operations: four groups of fresh keyed balance mutation, same-key retry, changed-intent retry. SplitMix64 chooses keys/values; keys increment with wrapping arithmetic so each distinct operation is distinct. Both graceful close and quiescent kill occur in every seed, alternating after each completed operation. Normal parents are seeds 0 and 1 only. No response loss, unfinished operation, fault injection, I/O pause, or exhaustive mode.

Execution: extend the existing real Host child protocol with ordinary keyed mutation and completed close messages. The child uses the genuine Host request, build identity and production open/mutate/close routes. A response is serialized only after the owned mutation result and borrowed owner observations are released. Quiescent kill occurs only after that response. Graceful close must return Closed and the child must exit normally. Reopen is a new child in every prefix. No reuse of live runtime after reopening.

Reference: one ordinary MemoryOnly Host, initialized once, using the same authored account program and inputs, retained throughout the seed. It has no Home binding, frontier snapshot/reset, durability door, checkpoint controls or recovery. HostOracleComparison retains its one DurableIdentityCorrespondence for the whole run. Compare initial state, after each operation and after every reopen: graph entities/relations/aspects/versions, World head and full occurrence ancestry, custody, and idempotency. Compare each immediate/recorded semantic receipt and handler-contact deltas. Assert expected committed/intent-drift fates explicitly so two equal refusals do not count as success. Reopen must not rerun initialization or handlers. Same-key retry after each group's first reopen exercises original receipt reconstruction; state is compared after every reopen.

Registration: the new normal tests live in the already-owned worth-store-court-application binary under process::application::host_oracle::graceful. The Store normal lane discovers this binary and includes process tests through nextest_build.LANES; its package has path dependencies on Native, World, Host and Query execution. The subject-to-lane reach planner therefore selects Store when any such package changes. Record the exact registered names and default range in the requirement map; do not add a second runner, ignored/exhaustive mode or baseline exception. Check the actual listing before running.
