## Decision

The remaining closure is not blocked by team ownership or by the local/external Native trait identity distinction. Move the actual runtime scenarios into external courts, retaining explicit provider handles and using the public normal-dependency runtime. Keep genuine value-only checks with their owner. That removes the identity problem rather than bridging it.

Most ordinary durable scenarios already have complete public paths. There are, however, exact private control/observation claims outside the cold family which cannot be called equivalent to a public happy path. These are identified below. They require explicit preservation (usually C2/private owner evidence) or a genuinely justified production capability decision before the associated test is removed. This review does not authorize retiring any assertion or exporting a private control.

The queue inventories remain navigation aids. A shared `recover_with` import, a `runtime()` spelling, or a file containing a durable branch is not a move decision. A durable fixture does bring every executing caller into the closure even when the caller has no provider vocabulary.

## External provider implementation prerequisites

The current external provider (`crates/worth-testkit-relational/src/durable_medium/mod.rs`, `attachment.rs`, and `bytes.rs`) is intentionally smaller than the local provider. These are decidable provider-owned implementation tasks, not production API or owner blockers:

1. Script the next commit and transition fate, including proven-no-effect, indeterminate-without-effect and indeterminate-after-effect. Record every actual offered artifact before applying the fate; store only the effects the script claims. Preserve identical-retry/next-position and next-sequence rules.
2. Add head/position and transition sequence/offered/byte observations, arbitrary byte replace/remove/duplicate and coverage-preserving checkpoint filing/damage. These observe externally owned bytes and need no private runtime access.
3. Provide fallible recovery-source frame reads. Current `recovery_source()` uses `expect` on held commit and transition frames, whereas `recovery_refusals::an_artifact_whose_frame_is_damaged_is_refused_at_the_read` and branch-transition damaged-frame tests require typed medium-read failure, not a panic.
4. Keep a provider-owned real I/O gate for publication concurrency. The existing local `slow_publication.rs` delegates public trait methods; it can be ported without a Native hook. This does not reproduce the separate private lifecycle/coordination rendezvous below.
5. Put semantic byte-edit helpers at the court/provider byte boundary. For example, `managed_field_text/missing_dictionary.rs`, `descriptor_continuity.rs`, `merge_replay_continuity.rs` and collaboration witness tampering must retain actual v5 frames and target semantic contradictions. Their inner private assertion subclaims must be preserved, not discarded while replacing the edit closure.

No provider extension above grants authority to construct private roots, arbitrary admitted bindings, sealed mutable envelopes or an in-crate Native runtime.
