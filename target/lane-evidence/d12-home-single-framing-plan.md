# Correct the Home capture/framing boundary

Fresh independent source review rejected mandatory predecessor framing on the
Home path. Agreed: this is a responsibility/phase flaw, not a budget-reporting
issue. complete::prepare currently encodes WSRCSRC1, after which Home binding
encodes WSRCAI01 and drops the first frame. Original work/funding must not pay
for an intermediate serialized predecessor.

Separate actual Section selection custody (original source, retained member
selection, selected-source owner and replacement progression) from framed DATA.
Ordinary staging keeps its existing single encoding and refusal order. Add a
runtime-owned CapturedHomeRelationalSection that owns genuine Native Complete,
its same selection custody and the image sealed under actual World coordinates.
Its consuming bind emits the final package once and produces the existing
PreparedCompleteRelationalSection. No empty frame, Option phase placeholder,
legacy Home reader or alternate selection/ACK path. The existing private Home
assembler still consumes actual World capture and only then installs the same
attempt. Coordinates are descriptive; they issue no authority.

Migrate the four Home operation closures and preparation/journey signatures to
the captured phase; obtain actual World coordinates before invoking Native.
Expose the one owning captured type through Store Relational's existing facade.
No dependency/feature/protocol changes. Exact files: Store Relational section
checkpoint/{complete,publication,selection_custody,home_capture}.rs, checkpoint.rs,
section/mod.rs, facade.rs; Store Application checkpoint/{preparation,journey,
operation,operation/controls_for_test}.rs. New type owns live source custody and
funded backing, so it belongs in the Store runtime, not a substrate.

Then coherent Store check, affected capture/package/ACK courts and failed bounded
proof. Do not assert the removal alone funds the41-original8m request. Keep the
coordinator resource-contract question open until a real bound is established.

four operation methods, two worldless receiver controls and one captured-Complete
