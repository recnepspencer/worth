## Findings

1. **P1 — Native kind reconstruction is not connected to original-request admission.** `region_load.rs:74`, `:87` and `:209` still call ordinary `rebuild`/`rebuild_head_history`; `resident_history.rs:138` also calls ordinary `rebuild`. The new `rebuild_for_request` and `rebuild_head_history_for_request` exist in `kind_projection/reconstruction.rs:49` and `:120`, but the facade exports only the ordinary functions. The Full loaders first share the Head adjacency tables and then reconstruct through ordinary mutable access. Ordinary map path copying clears node tickets on newly allocated paths, and ordinary kind insertion creates unfunded kind-map nodes. The new Full wrapper ticket funds only `ResidentRegion`, so those allocations no longer have the removed aggregate native reservation either. Head reconstruction still relies on wrapper funding that does not follow `PartitionState` extraction. This leaves both retained backing custody and denial propagation incomplete despite the funded image converter. **Correction:** export the two request-aware entrances through the existing private facade and use them at all four loader sites, preserving the request/storage distinction. Keep scratch admission for their temporary projections separate. **Verification:** focused cold Head/Full materialization and edit/freeze controls with nonempty current and historical peer memberships, including native reconstruction memory denial and successful retry. **Authority:** Architecture 16 and 19; the owner handoff's explicit request-funded COW/kind-map requirement. The pending facade scope ruling explains the unfinished integration; it does not make the current implementation sufficient.

2. **P1 — Head still admits native backing twice and retains the obsolete aggregate.** `region_load.rs:46-48` passes the complete raw Head quote to `MaterializationFunding::admit`. Its implementation at `materialization_funding.rs:258` reserves `quote.native + shared::<ResidentRegion>()` on the wrapper. That native quote still includes scalar columns, directory maps, metadata/Extra payloads, diagnostic maps, bitsets and native projection/frontier storage (`region_image.rs:17-171`, `:200-226`, `:252-279`). The same load now invokes `partition_from_image_for_request`, which reserves actual columns, maps, Extras, metadata and diagnostics at their native owners; prefix installation also reserves actual openings and prefix carriers. Both reservations remain live. This is an admission regression: a request can be rejected for two bills for the same retained native backing. The surviving wrapper aggregate also obscures which remaining ordinary Head allocations are actually funded. **Correction:** after the native reconstruction and commitment seams are connected, retain only fixed `ResidentRegion` backing on the Head wrapper. Preserve the independently necessary decoded wire and verification scratch through conversion; remove the replaced aggregate native reservation rather than raising budgets. **Verification:** a bounded Head request that fits its genuine simultaneous owners, typed denial below that footprint, refund/retry, and last-owner release. **Authority:** Architecture 19; Performance's named resource lifecycle and physical memory contract; the handoff explicitly requires removal of replaced aggregate native admission.

3. **P2 — Dependency custody does not yet charge navigation before every navigation step.** `history_custody.rs:25` executes `pending.entry_at(0)` in the loop condition before `work(request, 11 * usize::BITS)` in the body. Each base then pays only `work(request, 1)` before `seen.contains_key` and possibly `pending.contains_key`. Those reads are unmetered tree walks: `worth-execution/src/storage/ordered.rs:119-137` delegates `contains_key` to a lookup loop. A legal shared dependency DAG can have many already-known edges without triggering a metered insertion, so the once-per-member navigation allowance does not account for the independent edge lookup volume. **Correction:** admit bounded navigation work before selecting the next pending member, and charge the seen/pending lookup navigation for every edge before looking it up, using a named conservative bound or an existing appropriate metered read. Preserve the general admitted graph semantics. **Verification:** fixed output/local state with independently growing dependency closure and shared edges, original-request work denial before further traversal, unchanged retry and final provider custody. **Authority:** Performance's rejection-before-expensive-work rule; the handoff explicitly requires navigation and every visited edge to be charged. No new graph-depth cutoff is warranted.

4. **P2 — The exact proposed commitment extension covers raw Head, but does not settle the owned-Head expected-commitment path.** The patch adds `capture_head_for_request(partition, symbols, frontiers, request)`. Its `history_from_frontier` deliberately preserves the raw-Head condition that a nonempty history has exactly one materialized metadata entry. That is appropriate for the received Head image. However, `resident_history.rs:70-107` still computes an absent expected commitment with ordinary `capture_layered`, whose existing algorithm handles authenticated prefixes plus a possibly longer current metadata suffix. The proposed method cannot simply replace this call: a lawful edited Head can have multiple current metadata entries, and this new method would reject it. Leaving the fallback unchanged retains the ordinary allocation route. Its current `expected_memory` quote depends on physical record count and frontier sibling count, without explicitly quoting its independently varying adjacency commitment, resolved aspect-version vectors, current metadata suffix and construction scratch. Other live reservations should not be silently treated as the missing commitment quote. **Correction:** separately settle the owned layered temporary commitment: either use an original-request implementation that preserves prefix-plus-current-suffix semantics, or provide a complete concrete transient preflight for that unchanged temporary algorithm. If a further semantic owner is required, request that exact scope rather than treating the four-file patch as complete. **Verification:** owned Heads with an absent acceleration cache, multiple current versions, large aspect-version maps and independent peer adjacency, with equivalence, denial and retry. **Authority:** Architecture 10 and 16; Performance's carried-proof, named-lane and memory contracts; D12's bounded current state plus tails. This is an inadequacy of the claimed complete extension, not a reason to change artifact formats or reject legal current suffixes.

## What the implementation does establish structurally

The actual-backing repair is substantially better than wrapper-only retention. `StorageAllocation` holds `value` and its outer ticket in one shared allocation. Handle clones share that ticket. Funded raw extraction clones the value while destroying the original value together with its original ticket; outer-unfunded carriers preserve the ordinary move-when-unique path. Its fixed allocation layout now includes the backing wrapper. The audited production diagnostics/opening consumers share or replace carriers rather than mutating those newly outer-funded payloads. This supports keeping `lease.rs`, `PartitionState`, `current_edit.rs` and `full_edit.rs` unchanged. It does not qualify every future `value_mut` or raw-export caller.

Carrier-preserving dense construction and sparse defaults retain Extra, metadata, diagnostic and prefix reservations across column cloning and native edits. `ImageReadmission` routes one conversion algorithm through ordinary or original-request admission and preserves typed request stops through `funding::image`; a memory stop does not become permanent region damage. The arena converter checks every row-indexed column against generations, including `created_at`, `retired_at`, kind, lifecycle and all pin arrays, before slot fallback or conversion. The new local malformed-column test protects a useful part of that shape contract.

The custody leaf uses borrowed directory bases, funded ordered collections and an independently admitted final roster. It calls `RelationalDurableMemberCustody::capture`, which uses `retain_members_for_request` and checks the token's issuing source. There is no legacy retention fallback or new graph-depth refusal. `RecordHistoryCustody`, prefix carriers and openings retain the provider token past the original region wrapper. Finding 3 concerns work admission, not the issuing-source check or token lifetime.

The new `current_image.rs` replaces the whole `allocation_inventory()` prewalk with concrete wire cardinalities and payload visits. It reserves traversal stacks before native iterators, charges before inspecting aspect fields and diagnostic values, uses checked arithmetic, and quotes only the new wire storage rather than calling shared native storage a fresh native allocation. This is the correct boundary direction. The native reconstruction integration in finding 1 remains necessary after that preflight.

## Exact proposed patch verdict

The four-file commitment extension is **appropriate and useful as the raw-Head native commitment memory seam**, subject to the normal compile/equivalence proof. It stays runtime-private, changes no serialized field or hash domain, and retains the existing frontier ordering/shape checks, last-metadata validation, and caller obligation to compare the completed leaf. It funds actual frontier nodes and the last-value carrier, then reuses the funded Full builder for record, history-map, bitset and adjacency commitment owners and temporary row vectors. It avoids making a second content algorithm merely to add admission.

It is **not sufficient as an applied exact fix by itself**: the patch contains no loader call-site changes, does not remove Head's obsolete aggregate native reservation, does not connect funded kind reconstruction, and does not cover the owned layered fallback in finding 4. Its `poll()` calls consult cancellation/deadline/exhausted state; `ExecutionRequest::consult` explicitly does not charge work (`request.rs:262-264`). Integration must retain an explicit adequate pre-work charge for the actual reconstruction/hash visits rather than describing consultation itself as charging. Existing upstream concrete preflight can own that charge where its bound is demonstrated; adding a second work bill is not required for ceremony.

## The two new runtime controls

Do not assert that a later branch-root basis must retain this independent mirror allocation. A live current-edition observer must be released for the try-pass to proceed. This is a proposed corrected control, not an executed result.

## Follow-up: local transient layered commitment plan

The proposed correction to finding 4 can remain in the granted `current_image.rs`, `resident_history.rs` and existing funding facade. A complete original-request reservation held beside the temporary `expected` commitment until comparison is sufficient: that commitment never escapes, never funds the returned Full cache, and need not acquire a different actual-owner representation. The ordinary `capture_layered` algorithm can remain unchanged. This is design acceptance conditional on the concrete quote and call-site lifetime; it does not close finding 4 before implementation review.

I traced `capture_seeded`, `RecordContentIndex::update`, `record_history::update`, `AdjacencyContentIndex::update`, bitset delta capture and native sorted construction. The proposed counts cover the main axes: occupied record slots; every actual current metadata entry; actual prefix sibling counts and a prefix leaf; current adjacency slots/memberships in both directions; all four bitset word sets; and aspect-version row lengths. The records and adjacency slot vectors coexist across their respective two-direction captures. Cold record/history/membership vectors must include their actual distinct element layouts and growth/relocation coexistence. The resolved aspect-version vector uses `(&str, u64)` and exists only for one row at a time, so its maximum row length suffices for memory. Native history/membership maps store an inline two-handle `DigestIndex`; using the existing larger `SharedColumn<u64>` map quote is conservative. The existing `head_commitment_nodes` includes both inner and backing ticket layouts and more than one native map node per item.

Three details must be explicit in the implementation:

1. `changed_current_memberships(None)` and `changed_words_since(None)` allocate `BTreeSet<RelationId>` and `BTreeSet<usize>` through `SharedMap::changed_keys_since`, then consume those sets into `Vec<(RelationId, bool)>` and `Vec<(usize, Option<u64>)>`. Quote the B-tree nodes and output vectors at their overlap peak, not only slot/index vectors. Existing unused per-item map allowance may cover them, but the derivation must name those owners. `hash_value` streams into `Sha256Writer`; it does not require a whole encoded byte buffer.
2. A prefixed record retains a `HistoryLastValue` carrier. `DigestIndex::set` constructs its replacement before dropping the old carrier, so allow one per applicable record plus one simultaneous replacement carrier. The bounded Patricia path allowance must include the actual replacement overlap, not just final tree size. In this default-seeded, previous-None temporary capture, the constructed root is uniquely owned and only one record/membership/word insertion runs at a time; the fixed path allowance is separate from the final two-nodes-per-item allowance.
3. Work must bound bytes hashed and compared as well as counts. `record_digest` resolves an entity fingerprint family and every aspect-version Symbol to text, sorts the latter lexicographically, and serializes that text. Resolved text length can vary independently of row/version counts, and the current wire quote represents aspect-version map keys as fixed-size Symbols. Include resolved family/name byte lengths and a conservative string-sort comparison bound, or demonstrate an already admitted original-request bound covering them. Existing `current()` precharges metadata/Extra wire payload bytes; that charge can own the relevant payload-hashing allowance where the derivation demonstrates adequacy. No duplicate helper-local charge is necessary merely because a helper only consults cancellation.

Admit counting-walk iterator backing before iterator construction; charge navigation and each visited payload before inspecting it; use checked arithmetic; and perform the final calculated admission before calling ordinary `capture_layered`. With the above owners and work axes included, I found no inherent need for another semantic owner or a prefix/suffix algorithm change. Runtime denial/equivalence evidence and a read of the resulting narrow correction are still required.
