# Actual backing funding: early boundary review

Review posture: read-only source/design review against HEAD 0215c2872b and the concurrent worktree. No build, test, source edit, progress draft, report draft, or prior review conclusion was used. This is an implementation-boundary review, not final qualification.

Authority read: AGENTS.md, every document under docs/coding-guidelines, milestone-3 D12/D17, cold-materialization-owner-handoff.md, and funding-actual-owner-implementation-plan.md. The approved native owner scope and earlier ten residency owners are the implementation boundary. lease.rs, PartitionState, full_edit.rs, and current_edit.rs remain unchanged.

## Findings

1. **Material extraction requirement: the reservation must die with the original payload, including a unique raw export.** storage_allocation.rs currently wraps Arc<T>; stored_value.rs:31-32 exposes T through unwrap_or_clone, and shared_column/node.rs:184-188 calls it when converting pages into raw values. arena_images.rs:114 applies that path to diagnostic BTreeMaps. Merely replacing Arc<T> with Arc<Backing<T>> and returning Backing.value after unique unwrap would drop Backing.memory while its original BTree nodes survive in the returned map. That does not meet the handoff's actual-backing custody requirement. The smallest repair within the grant is to retain the reservation beside T inside the Arc allocation and, for an outer-funded allocation's raw export, clone T into the independently admitted output while destroying the original T and its reservation together. Preserve the existing move-when-unique path for outer-unfunded payloads, including node/Extra/Metadata values that already carry their own tickets. A private payload holder is sufficient; no new trait, blanket implementation, public surface, or edit-owner field is needed.

2. **Concrete claim mismatch: not every closed wire export visibly has independent original-request admission.** The two DATA conversion routes in region_load.rs and resident_history.rs reserve current-image wire before partition_to_image_with_contracts. In contrast, expanded_checkpoint.rs:266-280 takes Full partitions, drops their cells, and converts the partitions to wire through the ordinary converter; no wire reservation is visible in expand_regions or its expand caller. The implementation plan's blanket statement that exports go only into pre-funded wire is therefore stronger than the traced code supports. The native ownership repair can still preserve the existing ordinary image contract by using the funded-copy discipline in finding 1: no original funded native backing escapes. It must not claim that this also proves request-funded expanded wire. If original-request wire funding of expanded conversion is required, that needs an explicit additional caller/owner handoff; it cannot be inferred from the current grant or manufactured by the request-less ordinary image entrance.

3. **The closed edit routes support the proposed fixed boundary; generic COW alone is not proof.** Diagnostics have no production in-place payload mutation in the inspected owners. Arena merge and sparse clone use copy_value_from, which clones the StorageAllocation handle. Birth, suspend, and reset replace diagnostics with new empty maps. RecordHistoryOpening is read through the retained prefix and is not extracted or mutated by production edits. Prefix adoption and sparse cloning preserve its StorageAllocation handle. Thus moving or cloning PartitionState in lease.rs, then edit/freeze, can preserve original native tickets without modifying those owners. The implementation must preserve this distinction: cloning StorageAllocation shares the exact Arc and ticket; detaching a page shares its element carriers; ordinary COW of an outer-funded T cannot be described as a funded independent copy. Any newly introduced funded diagnostics/opening value_mut or native raw-extraction consumer would invalidate this ruling. Existing node, Extra, and Metadata tickets remain inside their existing owners and must not receive duplicate outer tickets.

4. **Carrier-preserving constructors and complete column validation are necessary, not optional simplification.** bulk_bootstrap.rs currently accepts Vec<T::Value> and reconstructs each element with T::from_value. Feeding funded carriers through raw values would discard the ownership distinction the repair introduces. Add the narrow dense entrance taking already funded T carriers and a sparse-default entrance taking an already funded carrier; keep scalar/raw ordinary entrances with their present meaning. Attach payload reservations before allocating diagnostics, readmitted Extra state, history openings, and their actual StorageAllocation backings. Use existing request-aware node/map/bitset/pin/directory construction for structural storage. Validate all row-indexed arrays against generations before constructing columns, including lifecycle, kind_ids, metadata_history, created_at, retired_at, aspect_versions, field_revisions, extra, diagnostics, and all pin arrays; the current zip of extra with kind_ids otherwise silently truncates. Slot fallback allocation also needs admission before its Vec is created. Remove replaced aggregate native charges only once these actual owners receive their reservations.

5. **One image algorithm with optional request is an appropriate private seam only if errors preserve their source.** Keep partition_from_image as the ordinary entrance and add an original-request entrance to the same private conversion pipeline. Thread an optional borrowed request to arena conversion, per-kind payload conversion, aspect readmission, adjacency reconstruction, and bitset restore. Use a concrete runtime-owned error distinguishing content/readmission failure from RelationalExecutionDenialCause. Exhaustively map malformed columns, duplicate slots, missing plans, and foundational denial to their existing content classifications; propagate admission, deadline/cancellation, and charged-overflow causes through the original request path. Do not map the entire result to Damaged at residency call sites. Optional request should select admission plumbing, not a second content algorithm, new validity rule, recovery lane, or authority type. This matches D17 placement and D12's bounded checkpoint/tail objective.

## Smallest safe implementation boundary

The granted files can implement the native repair: private ticket-bearing Arc backing; carrier-preserving dense/default construction; request-aware native image conversion with complete shape checks and typed error propagation; per-payload Extra/Metadata/diagnostic/opening reservations; existing funded structural constructors; request-aware kind reconstruction; and removal of replaced aggregate native funding. Keep source/wire/fold scratch alive until native conversion completes. Keep only fixed ResidentRegion funding at the wrapper. Update StorageAllocation layout_bytes to include its actual private backing layout so existing fixed/node quotes remain honest.

No native lifetime requirement discovered here calls for changing lease.rs, PartitionState, or either edit owner. Production clones preserve native carrier Arcs, and the funded raw-export discipline prevents the original diagnostic backing from escaping its ticket. Unique/shared extraction, edit/freeze, and last-owner refund still require the requested external observations; source review cannot substitute for those proofs.

## Verdict

**Proceed within the approved native-owner boundary, with findings 1, 4, and 5 enforced in implementation.** The per-backing design is structurally sound for the audited closed edit consumers. Finding 2 is an unresolved claim boundary: preserve the ordinary expanded-wire contract and report that limit, or obtain the additional owner scope if expanded original-request wire admission is part of the required guarantee. No final FUNDING LANDED, accounting adequacy, content equivalence, or qualification verdict is issued by this early review.
