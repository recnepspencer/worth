## 1. DurableStateFamily and creation mapping

One row below is one proposed variant. A variant is a semantic admission
family, not a new journal, store or recovery owner. Carriers and caller rows
are joined under the caller's name (R1): Query idempotency, activation,
workflow, outbox, inbound and causality rows use Relational's canonical
commit path. There is no `CallerRows` variant. M2 already persists native
graph/schema/branch/allocator truth; the application association is added in
Phase 4. The aggregate rows below preserve the four separately audited
native row kinds, not four competing identity authorities.

Classes are **A** authoritative, **M** mandatory obligation, **O** optional
retained. O expiry must answer `RetainedMaterialExpired`, never permission
to re-execute. R11 pinning makes correction material M until discharge;
transfers carry its class and pin. R4 diagnostics, retired D9 authorities,
and external products are explicitly accounted for outside the variant set.

Admission uses the union of kind and **all declared capabilities**, including
failure-only creation. A G mutation declaring L resources refuses until 7
even if it would succeed without cleanup. S resource-request admission also
waits for 7 (R5). Branch cleanup checks its actual component set: G=4,
S=5, conditional assembly=7 (R12). X outbox creation waits for 8 even if no
dispatch is attempted yet. N actions wait for 9 (R15).

All durable effect paths include cancellation, denial, deadline, panic/unwind,
abandonment, response loss and partial owner publication. Pre-effect
reservations/scratch alone stay local; after effects their logical obligation
must survive. R7 requires Phase 7/9 per-kind versioned data/readmission or an
already-defined typed terminal posture; opaque checkpoints, arenas, contexts,
closures and `Arc<dyn Any>` authority are never serialized.
