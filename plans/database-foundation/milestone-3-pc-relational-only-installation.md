## Boundary inventory

`prepared_meaning` currently builds that catalog before configuration or any
Native, Signal, Bridge, filesystem or World owner is constructed. Host owns
the one exhaustive `directory_family_support` table. Query must consume that
policy rather than invent phase constants at installation call sites. The
generic catalog shell reads two presence facts; a concrete core derives and
admits the complete fixed requirement list without per-schema policy codegen.

Signal-dependent installation inputs are:

| Input | Actual ordinary installation | Declared family |
| --- | --- | --- |
| Producer contracts, including feature producers | producer/scheduling.rs installs owned conditional routes | SignalNodeDefinitions |
| Conditional contracts, including workflow-stage targets and output-readiness dependencies | conditional install_all and installation.rs install bindings/readiness routes | BridgeConditionalDefinitions |
| ApplicationResource declarations | application_resource/installation/pool.rs installs owned-async request/response nodes for every resource slot | BridgeOwnedAsyncDefinitions |

The contribution tuple has five pending fields: handlers, producers,
conditionals, resources and managed indexes. Invariant factories install Native
rules. Handlers and partitioned-computation configuration retain Query-owned
executors; they do not install Signal definitions. Managed indexes are Native
indexes. Trusted authorization time and World resources are runtime services,
not authored Signal state. There is no raw Signal/Bridge installer argument in
the Home request. Later operation admission remains D15's responsibility.

All current resource pools are therefore unsupported directory seeds. A
Relational-only Home installs an actually empty resource registry, not a dropped
pending registry. Nonempty producer/conditional/resource retirement is outside
this ruling; existing refusal for still-live unsupported registries remains.
Actual handler/index/Native/Bridge owner retirement remains mandatory.
