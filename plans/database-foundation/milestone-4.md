## 1. Goal, Scope & Single-Owned Seam With Semantic Git

Milestone 4 closes the **Database Foundation Roadmap** by turning the crash-safe Milestone 3 Application Home into a sustained-use database that operates cleanly with **data and history larger than resident memory**, **durable branching with independent concurrent preparation**, **exact retained-basis historical access**, and **crash-safe, writeback-fenced physical space reclamation** — while keeping fork, local edit, checkpoint, reopen, and reclamation costs bounded by touched scope rather than total database or history size.

### Core Design Principles (Pragmatic, Fast-Feedback Cadence)

1. **Fast real-workload feedback first — no upfront proof wall.** Following Milestone 3 and `semantic-git.md` §12, M4 lands the O(1) whole-Home pin substrate **first (`M4.1`, unblocking Semantic Git Phase 2 immediately)**, real larger-than-memory eviction **second (`M4.2`, zero format bump)**, single-cutover chunking + paged reopen directories **third (`M4.3`)**, historical cursors **fourth (`M4.4`)**, and writeback-fenced reclamation **fifth (`M4.5`)**, closing with composed TLA+/DST/scale hardening (`M4.6`) and guidance/certification (`M4.7`).
2. **Assign each formal layer strictly to defects it can actually observe.**
   - **Verus:** small, pure, executable state-machine kernels only (`PinTable`, `AllocationGenerationGuard`, `ReclamationPlanValidator`) — never `Mutex`/`Arc` glue!
   - **Lean 4:** unbounded mathematical safety theorems where finite TLC cannot generalize (`StoreGCPinSafety`/`LeaseExpiryNoReaderLoss`, `AddressReuseGenerationAndWriteFenceSound`, `ReclaimPreservesAllReachableRoots`/`CanonicalCoverageBeforePrune`, `InterruptedReclaimIdempotent`, `ChunkedCoverageAndSummarySound`, `RetainedBasisCursorImmutable`).
   - **Composed TLA+ / TLC:** crash interleavings between every separate durable barrier (`ReclaimIntent`, `PublishFreeSpaceRoot`, `ReclaimComplete`, `AdmitToAllocator`, `WritebackIssue`, `WritebackLand`, `PublishForkPin`, `ExpireForkLease`, `Crash`, `Recover`) with non-vacuity witnesses.
   - **Seeded Rust DST & Courts:** real `Arc`/reservation memory custody, deadlock freedom, `cold == warm` agreement, real I/O headroom scaling, and observed production barrier/generation NDJSON trace validation against TLC.
3. **All 4 formal layers stay completely outside ordinary `./loop edit` compile closure.**
4. **Headroom and equivalent-path scaling proofs, never brittle fixture-specific page totals.**

## 3. Authoritative Architecture & Decisions (`D1–D8`)

### D1. Deadlock-Free Working-Set Eviction Bound on Real Allocations (`G1`)
- **The true memory bound is the sum of live `Arc<ResidentRegion>` `ExecutionMemoryReservation`s plus `raw_head`/`raw_full` load caches, symbol/lineage pages, and resident envelopes** — released strictly when the last `Arc` actually drops, NOT merely when `leases == 0`.
- **Root custody vs. resident guards:** Decouple durable member custody from operation-scoped resident borrows in `RelationalRegionRetention` (`retention.rs:95`) so a long-lived root never pins resident `Arc<ResidentRegion>`s in `OnceLock`s after operations finish. Clear `raw_head`/`raw_full` (`cell_load_cache.rs:8`) under the eviction protocol. Fix `RegionLeaseCustody::retire_native()` and `Clone` (`lease/cell_custody.rs`) so retired custodies cannot re-mint active counts, and treat lease count strictly as a **victim-selection heuristic** (preferring `leases == 0` cells first) while charging reservations until last `Arc` drop.
- **Exact evictability rule (M2 carry law):** A resident cell is evictable **iff** its current immutable bytes are bound in **this home's verified member directory** (never evicting `backing: None` cells from `resident_with_commitment`, dirty unpersisted deltas, foreign-runtime `checkpoint_bindings`, or clearing sticky `Damaged`).
- **Zero AB/BA deadlock:** Admission reserves memory budget **before** acquiring any cell `state` mutex. When reclaiming space under pressure, the evictor walks candidate victims using **`try_lock()` and skips busy cells** (never blocking on cell B while holding cell A!).
- **Rolling bounded windows replace whole-root demands:** Enumerate and convert M2's whole-root / whole-mirror declared demands (scans, maintenance, inspection, Full retention pass) and probe-retry "escalate to whole root" (`milestone-2.md:335-344`) to **bounded rolling windows** under separate head vs. historical working-set allowances.
- **Basis-preserving rewarm:** Rewarming verifies exact `BasisIdentity = (content_digest, schema_carrier_digest, level)` so updates, eviction, and rewarm can never expose stale warm state as current. Genuine saturation where all resident allocations are actively borrowed returns typed `RelationalStorageUnavailableCause::MemoryExhausted`.

### D2. Single-Cutover Chunked Placement Groups (`CHK24`/`REG8`), Authenticated Summaries & Paged Reopen (`G2`, `G3`, `G7`)
- **Single clean format cutover (`CHK24` / `REG8`):** Current `origin/master` writes `CHK23` (`native_checkpoint_codec.rs:9`) and `REG7` (`region_image.rs:13`). M4 performs **one** clean format cutover to `CHK24` / `REG8` in Phase M4.3 (no multi-step churn; pre-cutover `CHK23`/`REG7` homes fail closed with typed unsupported-format refusal or follow the repo's single-cutover migration contract, never half-migrated shadow readers).
- **Content-addressed chunked placement groups & per-slot continuation pages:** Subdivide large placement groups along fixed, non-overlapping slot-range boundaries into immutable, content-addressed chunks (`ChunkEntry { slot_range, semantic_chunk_commitment, head_summary, history_summary }` paired with checkpoint-authenticated `ChunkLocatorBinding { head_locator, history_locator }`).
  - `PartitionId` and `RecordId` identity never change. Small partitions remain single-chunk.
  - **Bounded per-slot continuation pages (`region_image.rs:60`):** Because a single record's version history or a single vertex's adjacency list can exceed the working-set allowance even when every individual value is small, subdivide intra-slot version chains and high-degree adjacency lists into bounded, content-addressed continuation pages under the same chunk/window memory guard.
  - **Consolidation-invariant semantic commitment:** Fold ordered slot ranges, **semantic chunk commitments** (derived solely from canonical chunk meaning, strictly invariant across history flattening/consolidation), and summaries into the selected root's Merkle commitment, while authenticating the mutable physical `head_locator` / `history_locator` mapping in the checkpoint manifest. Consolidating layered history (`milestone-2.md:420`) changes encoded bytes and locators *without* altering the selected root's semantic commitment, so pre-consolidation `RetainedBasisToken`s resume cleanly after consolidation + reopen.
  - **Producer-verified negative-summary soundness:** Every chunk kind/adjacency summary must be derived deterministically from (or verified against) the canonical head/history chunk projection **before** sealing its hash, AND cold readers must verify complete non-overlapping slot-range coverage against the slot directory before trusting a negative summary to skip a chunk (preventing both forged/stale hashes and pre-hash edge omissions).
  - **Chunk-wise capture consolidation & CoW edit:** Consolidate and copy-on-write edit dirty chunks (and per-slot continuation pages) independently so a placement group larger than memory never requires a monolithic `Full` load or whole-partition CoW witness.
  - **Bounded large-value streaming & in-flight fills:** Large payloads stream through fixed chunk windows under an explicit `MaxInFlightFillBytes` ceiling (zero whole-value buffers or unbounded background fill queues).
- **Mirror pin/lifecycle separation (`milestone-2.md:443`):** Decouple branch pins and lifecycle state out of the mirror so it ceases to be a second resident working copy of `main`.
- **Paged reopen & O(touched) checkpoint cutover (`G7`):** Page `PortableRecordDirectory` (`portable.rs:14`), **`RecordIdentitySubsystem` state** (generation high-water marks, reusable slots, pending reservations, and per-partition append frontiers: `record_identity/mod.rs:124`, `checkpoint_restore/record_identity.rs:14,49,127`), and manifest commit-index / patch-position directories (`cold_directory.rs:94`) into bounded content-addressed directory pages so reopen memory stays bounded under the same allowance as record cardinality and commit history grow `10×` (verifying exact slot reuse and outstanding reservations after a bounded-memory reopen). Reuse the exact kind-scan candidate path (`truth_kind_scan/directory.rs:19`), and replace linear route scans during checkpoint cutover (`publication_cutover.rs:49` -> `selected_manifest_pins.rs:104`) with incremental/carried pin sets so checkpoint and reopen both scale with touched scope.

  - **Independent branch preparation with stale-candidate Home-frontier composition:** Distinct branches prepare commits, cold chunk reads, and validation concurrently under branch-local `RelationalBranchCoordinationCell` without holding a whole-Store preparation lock. At the existing FIFO publication linearization point (`fork_publication.rs:143`, preserving M2's lock order `lifecycle admission -> branch coordination -> branch state -> patch-position reservation -> registry locks`, with Store's current-root/pin fence strictly nested as a leaf inside publication cutover):

    - Apply the branch's prepared delta onto the **current** Home frontier (so concurrent branch A + branch B prepared from the same frontier never overwrite each other's component root!), or return a typed retryable stale-candidate outcome.

  - **`PinTable` & `BranchLease`** (`worth-store` + `worth-store-application`, exposed upward via `RuntimeWorldRetentionPort` — defined by Mac `W1.1` if already landed, or defined directly in `worth-runtime-world` in M4.1 with Store Application implementing it and Query Host composing Store Application per `road1.toml:488-520`):
    - O(1) constant-write pin acquisition under Store's current-root / reclamation fence (`zero` base copy, `zero` record scans).
    - Persists across crashes & restarts, restored **before** any maintenance or reclamation runs on reopen.
    - Supports **transitive nested-overlay edges** (`NestedDropPolicy::{RefuseIfPinnedByChild, DetachParentKeepChildRoots}`), **in-flight durable decisions**, and **Memory-backend parity**.
    - **Reader-safe lease expiry (`Active → Expiring → Expired`):** Expiring a `BranchLease` atomically fences *new* reader loans (`LeaseExpired` / `ForkExpired`) while retaining the root pin until `active_reader_loans == 0` across the lease and any surviving nested children, then releases the pin cleanly. Named branches and immutable tags never expire.

### D4. Historical Retained-Basis Access & Resumable Cursor Tokens (`G5`)
- **Cursors are resumable position tokens — NOT unbounded durable retention pins:**
  - Extend `RelationalBranchBasisDescriptor` with a durable **`RetainedBasisToken`** binding `(home_incarnation, commit_id, root_commitment, schema_version, branch_origin, query_digest, canonical_key_position)`. Binding to **canonical key order + query digest** guarantees resuming after physical index discard never skips or duplicates rows.
  - **Resume-vs-prune loan fence:** Resuming a `RetainedBasisToken` resolves the exact basis and acquires an in-process **`ReaderLoan`** atomically under Store's reclaim fence, holding that loan through the last observable byte. Racing resume against pruning yields exclusively an exact read or typed `HistoryUnavailable` before admission.
  - **Restart semantics:** In-process `ReaderLoan`s end at process death. After restart, a `RetainedBasisToken` resumes cleanly iff its basis is still independently retained (by a live branch, archived branch root, immutable tag, active `PinTable`/`BranchLease`, or retention window); otherwise it returns typed `HistoryUnavailable` — **never silently rebinding to `HEAD`** and never leaking unbounded history.
  - **Typed historical disposition partition:** Strictly separate `HistoryUnavailable` (legitimately pruned), `UnsupportedHistoricalMeaning` (schema/version boundary incompatibility), and `CorruptStorage` (integrity/commitment failure).
  - **Direct historical access & canonical coverage:** Read retained records, versions, lineage, and schema boundaries directly from retained roots without replaying all intervening application operations or promoting history into the head working set; physical indexes and derived materializations may be discarded freely while canonical coverage reconstructs every promised view.

### D5. End-to-End Semantic-to-Physical Safe Reclamation (`G6`)
- **Complete `Reach` set (including all existing custody holders!):** Physical reclamation may release/reclaim pages, extents, or segments strictly outside:
  `Reach = live branch roots ∪ archived/retained historical roots ∪ durable PinTable & BranchLease roots (including transitive nested overlays & in-flight durable decisions) ∪ existing per-cell retain_members custody (cell.rs:103-117, cold_source/member_custody/) ∪ RootProtectionRegistry registrations ∪ latest & staged checkpoints ∪ pending recovery obligations`.
  - Respecting `road1.toml:525-560,650-685` (zero branch/MVCC vocabulary inside `worth-store/src/physical_runtime`), Store's physical reclamation planner consumes an **opaque protected-root/member set** projected from upper owners plus Store's own physical registrations (`PhysicalRetirementDenial::{Protected, Unresolved, Retained}`).
- **Canonical coverage before prune:** A journal segment, commit representation, or materialized base becomes prune-eligible **only after** a verified canonical successor checkpoint covers its live meaning (an accelerator/index never becomes the sole surviving truth).
- **Crash-safe, double-free-proof extent & segment reclamation:** Preserve Store's exact durable retirement ordering (`retirement_release.rs:125`, `resume.rs:101`):
  `RETIREMENT[_EXTENT]_INTENT` → `free-space root publication` (or segment unlink) → `RETIREMENT[_EXTENT]_COMPLETION` → **`allocator admission for reuse`**!
  - **Crucial reuse-before-completion invariant:** An extent MUST NOT be admitted to the allocator for reuse before durable completion (or must be fenced by `RetirementReleaseProjection` generation checks on reopen) so crashing after release + reallocation + write before completion can NEVER replay the release and free a live generation `g+1` range!
- **Bounded foreground cost:** Reclamation runs incrementally in bounded units off the foreground commit critical path so local foreground edits remain `O(touched)` regardless of total retained state.

### D6. Writeback-Fenced, Durable-Epoch `ExtentArena` ABA Protection (`G6`)
- **Scope strictly to the ungenerationed physical coordinate (zero Relational format change!):**
  - `RecordArtifactFile::Segment`, `RetiredArtifact`, and `DurableExtentRecordPlacement::extent_generation()` ALREADY carry durable generations. The only ungenerationed coordinate is **`RecordArtifactFile::ExtentArena { arena }` + offset inside `RecordFrameCoordinate`**.
  - Do **NOT** leak physical allocation generations into Relational's content-addressed `RelationalDurableMemberLocator`.
- **Crash- and cancel-monotone durable allocation identity:** Because Store can write a candidate extent, durably cancel it (`extent_copy/resolution.rs:161`), and return its range **without publishing a successor root**, deriving `ExtentAllocationGeneration` from root publication generation alone would reissue the same `(range, gen)` to the next candidate. Therefore bind `ExtentAllocationGeneration` to a **durable monotone allocation-fence epoch `(root_publication_generation, extent_fence_seq)` established on durable WAL admission before candidate I/O and strictly advanced on every extent cancel/release WAL barrier before that range can be reissued** — guaranteeing strict monotonicity across cancel → reopen → reuse even with zero intervening root publication.
- **P0 Writeback & Overlap Fence (Prevention, Not Just Post-Facto Detection!):**
  - A read-time generation check alone only detects corruption *after* a paused generation-`g` writeback has already overwritten generation-`g+1` bytes!
  - Therefore:
    1. Carry `(arena_id, byte_range, allocation_generation)` through `worth-store-buffer-pool` frame keys and **`writeback_claim.rs:209` I/O admission**.
    2. **Drain / fence every overlapping in-flight writeback and invalidate clean frames covering any overlapping sub-range (including split or coalesced extents!) BEFORE admitting a freed or cancelled range back to the allocator for `g' > g` reuse.**
    3. Reject any writeback or clean fault-in whose `allocation_generation` does not match the extent's active durable generation, and validate `allocation_generation` during recovery replay so stale references fail closed.

### 4.1 Split-Barrier TLA+ Shared Action Mapping (`StoreM4ScaleReclaim.tla` × `StoreDurability.tla` → `SemanticGit.tla`)

Every durable barrier is a **separate atomic TLA+ action** so `Crash` can interleave between any two barriers (never collapsing multi-step durability into one step!):

| Atomic Action | Coupled Modules | Exact Barrier / Coupling Condition |
|---|---|---|
| **`PublishBranchCommit`** | `StoreDurability` × `StoreM4ScaleReclaim` | Advances branch head & durable root publication generation (`root_gen' = root_gen + 1`), preserves sibling roots, records canonical coverage. |
| **`PublishForkPin` / `ExpireForkLease`** | `StoreM4ScaleReclaim` → `SemanticGit` | Captures `HomeRootManifest` pin atomically under reclamation fence (with transitive nested-overlay edges); `ExpireForkLease` moves `Active → Expiring` (fencing new loans) and moves `Expiring → Expired` (releasing pin) strictly when `activeReaderLoans == 0`. |
| **`RetireBranchRef`** | `StoreDurability` × `StoreM4ScaleReclaim` → `SemanticGit` | Permanently retires branch name and drops only the deleted branch's selected root pin while retaining sibling & live-loan reachability. |
| **`WritebackIssue` / `WritebackLand` / `CancelCandidateExtent`** | `StoreM4ScaleReclaim` | Models in-flight writebacks carrying `(arena, range, gen)` and durable candidate-extent cancellation without root publication (`extent_copy/resolution.rs:161`); `WritebackFenceDrain` blocks allocator admission while any overlapping writeback is active, and cancel/reclaim barriers strictly advance the durable allocation epoch before reuse. |
| **`ReclaimIntent`** → **`PublishFreeSpaceRoot`** → **`ReclaimComplete`** → **`AdmitToAllocator`** | `StoreDurability` × `StoreM4ScaleReclaim` | **Four distinct crash-interruptible barriers!** `ReclaimIntent` requires `range ∩ Reach == ∅` and canonical successor coverage; `AdmitToAllocator` admits strictly via **(a) completed retirement (`ReclaimComplete`) OR (b) checkpoint-covered candidate cancellation (`CancelCandidateExtent` covered by checkpoint WAL, `extent_copy/resolution.rs:157`)**, and in **both** paths requires zero overlapping in-flight `WritebackIssue`s (`WritebackFenceDrain`) AND strictly advances `gen' > max_seen_gen(range)`. |
| **`Crash`** → **`RecoverRestorePins`** → **`RecoverResumeFreeSpaceRoot`** → **`RecoverResumeReclaimComplete`** → **`RecoverServing`** | `StoreDurability` × `StoreM4ScaleReclaim` → `SemanticGit` | **Chained-crash interruptible recovery** matching `StoreDurability.tla:291`! `Crash` drops all volatile memory (`Arc`s, buffers, in-process loans, unlanded writebacks) and may fire again **between** `RecoverRestorePins`, `RecoverResumeFreeSpaceRoot`, `RecoverResumeReclaimComplete`, and `RecoverServing` — proving that a process dying after recovery itself publishes the free-space root (before recording completion) resumes idempotently without double-freeing reused ranges, restores durable `PinTable` before maintenance, and validates `RetainedBasisToken`s without rebinding to `HEAD`. |

**Mandatory Non-Vacuity Reachability Witnesses (in `StoreM4ScaleReclaim.cfg`):**
1. Delete a branch while a sibling branch and an active nested grandchild reader loan share its base chunks → sibling & grandchild succeed; unrelated garbage reclaims while pin is live; shared chunks reclaim once last loan drains.
2. **Paused old writeback fence (`P0`):** `WritebackIssue(range, g)` pauses while `range` completes retirement → observe `AdmitToAllocator` **blocked** by `WritebackFenceDrain` → release/cancel the paused claim → observe `AdmitToAllocator` **succeed** at `g' > g` (including split/coalesced overlap & candidate cancel without root pub) → verify a fresh submission carrying stale `g` is refused.
3. **Chained crash during recovery reclaim resume (`P1`):** Crash after `ReclaimIntent`, start recovery (`RecoverRestorePins` → `RecoverResumeFreeSpaceRoot`), **crash a second time before `RecoverResumeReclaimComplete`**, reopen, finish completion + reallocate & write at `g' > g`, and crash + reopen once more proving zero double-release of `g'`.
4. Concurrent `Branch A` & `Branch B` prepare from the same Home frontier, `A` publishes, `B` revalidates and applies onto `A`'s frontier (plus `B` racing `archive`).
5. Restart with a `RetainedBasisToken` after `HEAD` advances past it (and after history consolidation changes physical locators) → reads exact retained basis (and returns `HistoryUnavailable` once pruned, never `HEAD`).
