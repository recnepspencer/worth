# Phase5 Scene/Face and triangle Source boundary review

The next unfinished spatial path needs a real universe before an index can derive
candidate bounds. This slice establishes that model, Native eligibility and its
ordinary structural query in the existing topology entry and ConsumerSchema.
It does not claim maintained Source custody or spatial lookup.

Body/PositionX/Y and PlanarSuccessor remain Native geometry/contour truth. Scene
and Face are new actual entity kinds in a reusable optional SceneFaceContribution.
SceneFace has unbounded outgoing membership and exactly one incoming membership
per Face. FaceAnchor has exactly one outgoing Body per Face and optional-at-most-one
incoming Face per Body. Thus old Body records remain valid, Scenes may be empty,
Faces cannot be orphaned, and Source root dedup cannot merge two distinct Faces.
All relations are same-context and reject deletion with live relations.

AttachPlanarFace uses an actual existing Body selector, creates a Face and its
Scene (when absent), and writes both physical relations in one real candidate.
The operation's decision reads track key selection and retain the Body mutation
target; keys name entities but never prove contour identity or eligibility.
CandidateWriter::create_entity uses the command's issued creation partition, which
does not establish same-context membership with an existing Body. Scene and Face
creation must consume create_entity_in_context with the genuine projected anchor
selector. Existing Scene linking remains subject to Native context refusal.
One Scene contains faces in that same Native context. Existing CreateCycle commands
issue fresh contexts; attaching such a new contour to an older Scene must refuse,
while attaching it to a newly created Scene in its actual context is lawful.
No coordinates, cached bounds or copied Face identity are stored on Body.

TriangleFaceContour is an installed blocking Native rule. The actual proposed
successor chain must contain three distinct full-generation Body IDs and return
to its anchor on exactly the third step. Existing PositivePlanarTurn supplies
orientation; the new rule supplies only supported contour shape. Bounded affected
selection uses touched Faces and touched Bodies plus at most two predecessors,
from both committed and proposed images. Old selectors are reobserved through the
existing same-proposal public door; no raw IDs create read authority. Preparation
admits the exact proposed anchor/successor scope and evaluation consumes it.

An executable parameter-free structural query scopes Scene by SceneKey and follows
Scene -> SceneFace -> Face -> FaceAnchor -> Body. Its Body row projects root XY,
one-hop predecessor/successor XY and reverse FaceAnchor FaceKey/actual identity.
Composed unguarded root paths and these one-hop child slots are supported by the
current query compiler. Nested child projections and child-only Source ordering
are unsupported; neither is required. No managed provider is installed merely to
obtain Source custody. The next spatial slice will bind this exact query as Source.

ConsumerSchema keeps its owner and opts into the fourth contribution through a
minor version bump and matching host tuple. Its actual program rule roster includes
TriangleFaceContour. Its feature roster must also own the AttachPlanarFace action:
execute_in_program rejects a binding absent from that actual program. A dedicated
SceneFacesFeature with ordinary source completion owns the new action, rather than
placing scene authoring in an unrelated planar-output feature.
Existing isolated schemas do not opt in. Existing v1 planar
queries, topology scope, policies and negative-control meanings remain unchanged.
Installation/checkpoint tuple changes apply only to ConsumerSchema owners.

Independent boundary review accepted this coherent model/eligibility/ordinary
query slice and explicitly denied any maintained Source or spatial completion
claim. Unsigned boxes, maintained provider, collision refinement, locality courts
and Phase6 remain subsequent work.
The rule adds no independent work ceiling: original request and Native read controls
own refusal. A per-rule allowance of None preserves those controls without adding
an arbitrary admission policy. Construct one proposed evaluation view per invocation;
its touched-list clone must not be repeated per affected Face.
