# Phase 2 prerequisite: one truthful Source preparation work account

## Boundary review

The next unfinished acceptance is whole-path geometry growth. Review found a
prerequisite defect: Native's pre-invariant Source stage retains per-program
custom meters but never settles their unfunded work into the original SDK
account. Serial SystemAllocation omits even the shared preparation budget.
Provider bounds/navigation alone therefore cannot qualify Source/reverse routing.

Query provider checkpoints currently debit both the custom Source meter and the
SDK context. Blind settlement would bill those units twice. Native aggregate
reads already distinguish genuine SDK-funded work from deferred custom work;
the managed provider must use the same distinction at the actual Native receiver.
Installed rule allowance remains independent of the original request ceiling.

The actual SDK context owns effective accounting, remaining work and ancestor
controls. An allocation policy or a fresh lease cannot substitute for it. Source
visits must charge that actual current context and consult its inherited controls
as they proceed. Any retained affinity backing must be admitted before allocation
and remain charged until its final owner releases it.

Source roots remain speculative during preparation. Charging work immediately on
both successful and refused paths must precede result handoff. Original request
work exhaustion/cancellation wins with its exact typed cause and SDK stop latch;
an installed per-rule limit remains a Source/rule refusal. Native-funded provider
units enter the SDK invoice once and still consume the installed rule allowance.

The independent review also found whole-registry managed-handle scans in SDK
publication. That separate owner repair and actual 1,000/2,000 chain, 50,000
unrelated geometry and retained-query axes remain required after this prerequisite.

## Revised boundary: immediate work on the one SDK account

Implementation review exposed a mixed-charge defect in deferred settlement:
custom Source work can consume its captured remaining allowance while nested
Native work spends that same remaining allowance directly. SDK intentionally
rejects a late over-ceiling completed-work invoice without charging it; settling
afterward would omit performed Source work. Do not weaken that SDK contract or
accept speculative double allowance. Replace the uncommitted deferred design.

Use a sealed work loan issued by the actual active KernelContext. An immutable
parent-linked affinity cell, funded by the original payer, is inherited only
through genuine RunLimits. The active scope guard closes its own cell even if
prepared contexts retain its data. Loans charge the actual current descendant's
existing counter once; normal report aggregation carries it to the parent.
Closed or foreign scopes refuse. No additional work counter or identity registry
exists. Native-only mode polls, and every custom safe point sees the actual
active SDK controls, so no copied control-status snapshot is needed.

## Implementation plan

1. Add the scope-bound SDK work loan described above. Check actual active scope
   identity and liveness, inherit the linked affinity through RunLimits and worker
   contexts, and close only the issuer's cell on scope exit. Admit the identity
   backing through the original request before allocation. Ordinary scopes that
   issue no loan allocate no cell. Keep scalar-only request counters authoritative.
2. Add a Source-stage custom budget holding that loan and original retained-memory
   payer. Source custom visits charge the loan immediately; installed per-rule
   limits stay distinct. Remove the abandoned deferred Source budget/settlement,
   request-work-exhausted flag and copied-control-status code.
3. Add Native `CustomInvariantReadBudget::checkpoint_native(context, units)`.
   It validates the supplied context is the actual active authorized descendant,
   checks the original read request, debits rule allowance and charges the actual
   SDK context (or polls native-only mode). Query's controlled provider
   checkpoint closure routes optional Source budgets through this receiver rather
   than charging custom work separately. Preserve the first concrete refusal.
4. Run pre-invariant Source preparation in one original SDK scope. Create one
   shared custom budget; complete discovery and provider staging through its
   immediate loan. Preserve actual first SDK work/cancellation/overflow stops
   across the outer handoff and keep installed rule refusal separate. Do not
   sum per-program meters, settle work twice or replay staged work. Extract preparation
   substeps by responsibility as needed to keep touched files within 400 lines.
5. Extend the existing Native registered-Source court with participants differing
   only by a fixed additional custom or genuinely SDK-funded K checkpoint.
   Compare real report invoices, including Source/provider refusal. Require K
   once, exact request WorkExhausted at an insufficient ceiling and no head
   movement. Separately exercise installed rule allowance and parent cancellation
   after entering serial Source preparation while the child token stays live.
6. Run the existing real public geometry family as the Query integration
   regression, plus narrow context/control tests where they convict the new
   receiver. Keep synthetic meter tests limited to private accounting mechanics;
   actual Source acquisition and publication come from the existing real court.
7. Document only this repaired accounting boundary and remaining growth work.
   Preserve the unrelated milestone draft. The independent reviewer gates
   qa-loop, qa-tests and code-quality-qa before committing.
