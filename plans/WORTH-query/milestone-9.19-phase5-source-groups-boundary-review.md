# Query 9.19 Phase 5: Native Source preparation groups boundary review

Status: reviewed prerequisite; Phases 5 and 6 remain unfinished.
Baseline: `9923e500023ea14061c3d9939b8467848f8816a5` (also pushed master).

## Verified boundary

Phase 5 requires Bank and topology adoption through real public receivers, with
original principal/capability, pinned-read, lifecycle and work contracts intact.
Bank account discovery is a genuine three-path principal/account union. Its
existing v1 unit request, empty parameter binding, AccountId order, 1024 declared
limit, DiscoverOwnAccounts ability and current-and-pinned basis are executable
contracts. Managed historical READ currently refuses moved retained images.
Adding an implicit all probe or silently replacing v1 with that narrower receiver
would break compatibility. A later adoption slice must retain v1 and declare a
distinct explicit current-only contract, or implement genuine historical READ.
No Bank declaration or behavior changes in this prerequisite.

Native currently derives Source postings, historical program slots, authored
impact preparation and pre-invariant staging directly from
`CustomInvariantRegistration`. Source preparation uses only the installed program
list, declared access and maximum work metadata; it does not use a rule callback,
semantic rule identity or invariant execution point. This coupling prevents a
public-only maintained Source from joining the real preparation path honestly.
A dummy/no-op invariant would create false ownership and is forbidden.

The actual authoritative programs are schema-bound `ManagedIndexSourceProgram`
Arcs. Their pointer equality is installed runtime affinity, not portable meaning.
Rule registration validates complete read/affected access and same scope kind.
Routing includes scope/row and all membership/projection endpoint kinds. History
uses one deduplicated exact-program roster; retained selectors bind that roster.
Staging discovers every program before provider invocation, unions sibling
invocation scopes within each actual rule group, and keeps the first affected
rule group's access/work ownership for a repeated exact program. Actual Source
preparation uses the original request stage and Native participant/epoch; provider
publication and exact observation custody remain unchanged.

## Slice authority and handoff

Extract one immutable private Source preparation group, derived at registry
freeze from each actual rule with Source requirements, in existing rule order.
The group carries only exact programs, access and maximum work. Freeze one group
roster in the existing registry. Source postings index group slots; the history
catalog and both real preparation receivers consume that same roster. Real rule
inventory/index/iter/get and callback execution remain owned by the unchanged
rule registry. Empty rule groups produce no Source posting or history entry.
This is a complete internal handoff cutover, not a second registry or a new
public Source registration capability.

The Source receivers must cease depending on whole rule registrations. No new
budget, Source scan, provider API, fixture family, historical READ, portable
format or authority proof is introduced. Existing constructor/recovery/fork paths
continue deriving or cloning groups from precisely their existing rule inventory.

## Dirty edges and subsequent prerequisites

Preserve affected-group order, program identity, multi-program invocation union,
first affected owner, access denial, original budget lease, authored no-op history,
selector affinity, empty completeness and typed errors. Do not deduplicate groups
before routing; two rules with different affected audiences can own different
first-selected work policies. No traversal or matching algorithm changes.

Before a later slice permits explicit public-only groups, extend every builder,
initial installation, recovered codec transition and recovery/bootstrap receipt
handoff. Current initial/recovered proofs compare only invariant inventory and
schema authority; explicit Source roster loss would be invisible. Keep the public
rule inventory digest rule-specific and bind genuine installed Source meaning
separately at that future cutover. Validate all Source paths/routes against the
receiving runtime registry. Portable maintenance policy/versioning also remains
future work; old v1-v4 bytes and meaning must remain unchanged.

Topology currently owns real component/orbit preparation and checked determinant
evaluation, not a removable spatial cache. Its later box adoption must replace
actual discovery without deleting topology truth. Neither Bank nor topology
qualification, nor Phase 5 completion, follows from this prerequisite.

No unresolved material facts remain for the internal metadata cutover. Whether a
new Bank contract or genuine historical READ is the final adoption solution is
outside this unchanged-behavior prerequisite.
