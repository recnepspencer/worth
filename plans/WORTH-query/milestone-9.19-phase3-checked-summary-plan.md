# Phase 3: checked summary traversal and local candidate membership

## Boundary review

The exhaustive profile now makes Query own actual complete Source-tree traversal.
It deliberately cannot prune. The existing provider-controlled BVH query remains
the maintained geometry candidate path. The next vertical must replace that path
with Query-controlled traversal whose skips have a checked summary premise.

The private SourceTree already proves exact Source occurrence coverage and one
connected acyclic tree, and retains region/parent/Source maps in the same typed
ProviderNodeBacking as the immutable actual nodes. Native and public selection
owners retain the exact Source/root pair and original admitted session; preserve
those owners. A new proof issuer, registry, root token or parallel summary cache
would duplicate their custody. Installed definition/provider version, Source,
Parent graph, ordering and result shape already have exact typed correspondence.

Two influence restrictions are prerequisites. First, decompose currently borrows
all Sources even though warm reuse assumes unchanged Node implies unchanged
descriptor. Make decomposition Node-only. The small public box adapter currently
resolves ordinal leaves during decomposition; convert its cold pure ordinal nodes
to genuine Source-slot nodes during construction instead. Prefix and maintained
box nodes already contain genuine slots. Second, a summary callback cannot read
arbitrary Sources: another subtree's row could change without entering this
node's affected ancestor closure. Provide a narrow SummarySources receiver whose
only row lookup checks the slot's actual Source-node ancestry against the current
checked region before returning its genuine row. It exposes no global enumeration
or Source count. Charge these map/parent checks on the original control.

The provider owns pure summary algebra and comparison meaning. Add a Copy + Eq
Summary associated type and pure source/merge/node/exclusion operations, bound to
the same installed provider/version. Query reconstructs each summary from actual
own-row contribution and already-qualified child summaries, then checks equality
with the summary in the actual immutable Node. Query does not accept a provider
assertion that an arbitrary region was validated. Qualified pure tests establish
the algebra's domain meaning; Query checks its actual application and custody.

Cold qualification traverses the checked tree bottom-up. Warm qualification uses
actual surviving writer edits plus actual Native before/after Source owner nodes,
then their entire final ancestor closure. This must include a Source value change
even when the provider writes no Node, and must propagate past equal Summary
values when summaries reference Source slots. A concrete postorder walker visits
the induced ancestor-closed affected tree, skipping unaffected subtrees; children
qualify before parents. The cached child summary is the same value just checked,
so no second computed-summary truth needs retention. Deleted nodes' summaries
retire with their actual Node backing.

Prefix summary material is the lower/upper genuine Source coordinate. Its pure
AVL owner refreshes these extremes along with height through insert/remove and
rotations. Restricted resolvers read the current names of those coordinates.
Box nodes already carry the exact enclosing Box2; leaf summaries come from actual
Source bounds (including indirect endpoint regions), and branch summaries union
their actual children through the numerical owner. Generic Query contains no
prefix, box, field, tolerance, unit or frame policy.

Query alone decides visit/skip using the actual retained region and its qualified
summary. A false installed summary predicate discharges precisely that subtree;
it cannot emit a candidate or assert global coverage. Retain the actual checked
root coordinate in SourceTree, not an independent version/stamp, so traversal
cannot begin at a convenient child. Positive membership still uses the pure
matches_source callback on actual framework-selected rows. Ordinary projection,
ordering/cardinality and fresh governance remain unchanged. Complete conservative
Source dependencies remain: no transient boolean or visit count becomes Phase 4
legality. Its later receiver must bind the actual visited/pruned frontier to the
exact admitted query/root/basis/audience and tracked refinement.

1. Make decompose Node-only and port the real adapters. Keep hostile structural
   roots based on genuinely observed Source slots. Prove the existing cold and
   warm structural courts still retain their exact causes and lawful twins.
2. Add the portable checked-summary Source-tree strategy alongside Candidates and
   ExhaustiveSourceTree. Preserve their wire/canonical semantics and require
   BinarySourceTree for both complete strategies. Bind its tag through existing
   definition v3, provider/version and actual typed installation comparison.
3. Add the typed Summary and narrow SummarySources contract. Implement region-
   confined Source lookup through actual map/ancestry checks; no public constructor
   or retained mutable owner is exposed. Pure callbacks default to typed
   unavailability for providers that keep a different strategy.
4. Qualify actual summaries only after Source topology/delta admission and before
   root retention, with fixed controlled callback shells and concrete affected-set
   and postorder graph mechanics. Paid scratch uses existing SDK ordered maps;
   warm work never enumerates the whole Source or node roster. Latch structural,
   summary, decoding, request and allocation refusals without replacement.
5. Extend framework coverage traversal to discharge an exact checked subtree from
   its qualified summary predicate, with final control/Source checks before any
   result. Keep explicit exhaustive traversal working independently. Remove the
   maintained geometry provider's displaced ordinary query implementation.
6. Add/refresh pure prefix extrema and pure bounding comparisons; port prefix,
   small public box and maintained geometry to the same checked strategy. The
   explicit-rebuild prefix application retains ExhaustiveSourceTree so its real
   complete-walk/interruption court continues to protect that strategy; the
   maintained prefix application opts into checked summaries on both public and
   invariant reads, through its actual application policy constant. Name
   observations for their actual callbacks: probe validation, summary comparison
   and Source matching. Ordinary node-read observations stay at actual node reads.
