# 9.19 Phase 2: explicit maintained rebuild

## Boundary brief

The Parent session and the Source binding independently own Query READ admission,
principal/scope/Product agreement and provider purpose. Native owns the exact
SnapshotHandle, registered live Program, physical Source association, relation
occurrences, selected dictionary and cache slot. A retained handle is no READ
or currentness proof. VisibilityProjectionView already owns an exact selected
basis without runtime guards and supports original-request region demand.
The pinned relation evaluator already consumes that projection through the same
registered recipe evaluator used for invariant Sources. Reuse it; never invent
an invariant observation, audience, proposed scope or alternative evaluator.

Query owns the compiled projection, persistent row material and provider nodes.
Those must enter the existing ManagedSourceRoot and Native cache, not standalone
ReadyIndex. Native must compare the captured entry at install; eviction/refill
races refuse without effects. Preserve association/revision for an unchanged
Source. Provider callbacks and retired backing destruction occur outside runtime,
registration and cache locks. A completed install must survive outer late polling.

1. Factor selected-projection relation evaluation from the existing pinned path.
   Add a sealed Native rebuild loan from a genuine selected SnapshotHandle and

2. Share managed occurrence/projection materialization across invariant and
   selected loans using a closed prepared-read wrapper. Validate each proof

   memory/work admission. Keep relation multiplicity and full-generation checks.
3. Add Native compare-and-install on that exact cache entry with retirement
   carried beyond guards. Keep Source association stable. Recheck registration
   on completion and reject changed/foreign selected custody.
4. Route maintained public rebuild through fresh Source acquisition/purpose,
   canonical material/provider construction, and that install. Capture the loan
   inside the genuine ordinary Source READ body; keep its truthful ordinary
   query counters and completion. This bounded reconstructive lane walks Source
   twice (admitted ordinary query, then Native occurrence projection), both on
   the original request. Its first-pass Source image/allocation remains through
   purpose completion; combined cold peak is real cost, not warm-growth evidence.
   Pre-admit status completion and preserve completed effect across outer request handoff.
   Existing standalone behavior continues until its scheduled lifecycle cutover.
5. Extend public geometry court: refill cold material, reuse retained Source
   expectation, cancel provider build and retry, and consume rebuilt material in
   a subsequent real invariant mutation. Add narrow Native race/affinity owner
   proof where public controls cannot expose an intervening cache edit.
6. Run narrow typecheck/tests first; then boundary/context, format, dirty caps,
   function advisories and independent qa-loop/qa-tests/code-quality-qa gate.
   Commit the coherent slice after approval.

Initial Cold::Refuse bootstrap is not claimed here: program activation precedes
seed rows and needs a genuine initialization route. Other Phase 2 lifecycle,
