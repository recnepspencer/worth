## Boundary review

The source intent, installed program action, current principal, request scope,
and idempotency key enter through Publication's selected-program mutation path.
That path owns admission and the action receipt. The producer registry and
installed output graph own producer applicability and discovery. A caller's
list of connections is not publication custody or a dependent-set proof.

Native's existing coupled assembly owns a real unpublished applied candidate,
its symbols and identities, sequential application, and the final proposal.
It already carries independently authorized producer attempts into one World
publication, with final-candidate support checks. Its present source posture is
limited to authored retirement/restoration; its participants are surviving
source-owned Preserve publications. An ordinary edit, Birth publication, or
dependent discovery cannot honestly be represented by those postures.

Extend that owner instead of committing drafts on a private branch. Current
publication custody and route presence remain the existing Native owners;
there is no alternate roster or history-based currentness reader. The canonical
envelope must distinguish an ordinary edit from retirement. Every participant
keeps its own operation admission, source observations, output witnesses and
lineage. A candidate parent is not a committed settlement.

The final transaction is the only publication, adoption, trigger and receipt
boundary. Failure before it discards the source and every participant. The
larger transaction retains all read and write conflicts. Current readiness and
measure queries remain reads. Explicit demand-only output graphs retain their
declared delivery meaning; they must not be silently promoted to synchronous
required output graphs.

Native's canonical publication `basis` is the transaction's C, not an individual
coupled writer's applied input D. The #84 retention owner currently retains that
C for Preserve origins. When the authored prefix changes a source, returning C
would report the wrong consumed inputs. A coupled publication must not issue
that basis as its input observation. The retention owner must carry the actual
pre-writer applied image, authenticated to the performed route; an unretained
image remains typed unavailable. This requires a distinct read posture, since
an applied image is not an admitted committed branch basis. Permissions remain
at current C. The existing #94 restoration-origin refusal remains in force.

The measured cabinet journey includes repeated computed-slot producer paths;
the stack frame alone does not establish why a producer ran. Trace actual
currentness and completion before eliminating a call. Ownership-delta and hash
implementation belong to pub-core and are excluded from this change.

## Completion and exclusions

The envelope is explicit at the request boundary. Its intended call shape is
`request.advanced().edit().mutate(source_intent).seal(document_intent)` followed
by one idempotency key and `execute_in_program`. The concrete types remain
owned by Publication and Query; each stage retains its own installed binding
and independently admitted current authority. Authored stages, including the
seal, prepare before derived discovery, so producers observe the final authored
generation and name frontier. A stage token may expose a typed result only from
the committed envelope that issued it. No transaction or success is ambient.

For fixed or discovered required outputs, the existing source-retention entry
already has the concrete graph and source mapping before publication. That is
the handoff to carry into assembly; the current `Performed`-then-derive sequence
must become preparation-then-one-publication. Generic completion-only mutation
calls must not manufacture that graph from names. Explicit coupled declarations
remain the handoff for retirement connections derived from a pre-image.

Acceptance is one physical Relational commit for the authored edit, all
synchronous consequences and seal, with one visible transaction and unchanged
refusal strength. A later commit requires an explicit deferred declaration;
ordinary required output graphs are synchronous. No deferred case is assumed.

No P5 READY until all stages and evidence are complete. Public #93, further
history features, ownership deltas, hashing, and proprietary consumer edits are
outside this slice. Root owns independent certification of #84 and sends any
findings for immediate priority.
