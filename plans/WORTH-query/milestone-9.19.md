# Milestone 9.19: Managed Advanced Access And Verified Footprints

> **Status:** In progress. Phase 1 complete; Phases 2–6 unfinished.
> **Scope revised 2026-10-27:** the general managed derived-index extension owns
> the spatial-index finding formerly assigned to 9.18.1 Phase 12 and the dependent
> CAD locality qualification from Phase 15. Proprietary cutover is the final phase.

## Goal

Let applications install their own typed derived indexes and access providers,
then query them through the ordinary Decl/Host surfaces on an exact committed or
candidate basis. Query owns the lifecycle, tracked source dependencies, query
invalidation, admission and publication. Providers own their index representation,
incremental algorithms and typed query meaning. Adding a provider must not require
another index-specific subsystem in Query or Relational.

The first required uses are a geometry box index and a nonspatial name-prefix
index. Both must use the same extension and both read postures. CAD then adopts
the qualified public capability once, at the end, for arrange pair discovery and
installed B-rep contact validation. This closes the retained spatial-view gap
without making spatial meaning part of the generic runtime.

### What Must Be True At Completion

- An application declares and installs an index provider using only
  `worth-query-decl` and `worth-query-host`; its pure value/algorithm owner remains
  Query-agnostic. Providers extend the same public contract without framework
  branches for boxes, names, faces or operation families.
- Committed preparation reads and proposed-state invariant reads use the correct
  managed index roots. Incremental updates include all declared indirect inputs;
  refusal or cancellation preserves committed truth and its index.
- Candidates and dependency evidence remain complete through insertion, deletion,
  motion/rename, generation replacement, branch changes, rebuild and disclosure
  change. An empty result remains dependent on things that could enter it later.
- Exact domain refinement is distinct from candidate discovery. Query verifies
  the realized influencing footprint before it narrows dependencies or conflicts;
  neither an index result nor provider assertion grants authority.
- Ordinary local work follows the semantic delta, relevant dependency closure,
  index structure and actual candidates. Hidden full-source rebuilds, scans of all
  retained queries and per-result child lookups cannot satisfy locality claims.
- Public bank/geometry journeys, a genuinely nonspatial provider and the final
  Proprietary adoption pass on the integrated implementation. Superseded consumer
  caches/orchestration are removed during their respective adoption phases.

### Scope Boundaries

This milestone extends 9.10's graph-read plans and 9.16's ordinary admission; it
does not create another query language, authorization path or view registry.
Typed correlated path programs and provider set execution remain 9.20, governed
decision attachments remain 9.21, and cross-attempt stage sharing remains 9.22.
Durable index archives and restart-stable provider state are not implied: retained
indexes are disposable projections, rebuilt from authoritative truth when their
declared lifecycle permits it. An unavailable index never silently becomes stale
truth. A custom derived relationship can use the extension's managed evidence,
but does not thereby bypass graph-law, traversal or mutation contracts.

Addendum 1's withdrawn partition-reuse finding is not scope to implement here.
Query's existing partitioned managed computation already supplies declared keys,
tracked gathering, pure `compute_partition`, owner completion and per-partition
reuse retained on the producer record at the report's `ba86433627` SDK. The
one-retained-computation-per-handler constraint is handled in the consumer's
design. This milestone adds the missing managed-index lifecycle and both range
read contexts; it does not replace that computation engine or require relaxing
the handler limit. Pair discovery and retained pair certification remain distinct.

## Adversarial Constraint

A provider omits candidates after insertion, deletion, motion, capability
change, and rebuild; leaks a protected candidate through ranking, count, cursor,
or timing-class metadata; understates memory; widens a footprint; and reports
returned rows as complete dependency evidence. Independent full-scan and
resource oracles must expose every lie.

### Decisive Public And Private Journeys

Use actual installed queries and operations through Decl/Host, original request
controls and genuine source generations. Run a geometry box provider and a
name-prefix provider through the same lifecycle. Query an empty box/prefix, then
move or rename a previously unrelated record into it. Previously retained
observations must invalidate. Retire/recreate a source at the same slot, fork the
basis, revoke disclosure, cancel during candidate maintenance and evict/rebuild
the index. Independent exhaustive reference results must expose omissions, stale
roots, fabricated membership and unauthorized influence. Full-scan references
belong only to certification, not ordinary execution.

In a 1,000-vertex geometry chain, move a middle vertex so an incident edge meets a
non-incident cell. Preparation discovers candidates from the committed index;
the installed invariant queries the candidate index and refuses the new contact.
A non-contacting twin commits. At 2,000 vertices, hold the edit, incidence and
candidate density fixed: work may change with tree height, not a full rebuild.
Repeat discovery beside 50,000 unrelated faces. Separately increase unrelated
retained index queries to expose a scan-all-query invalidation implementation.
Dense legitimate overlap may increase output and candidate work; no constant-time
claim applies to arbitrary distributions.

Early phases qualify this sequence on public production-valid fixtures. Final
Proprietary acceptance repeats the decisive geometry boundary through the actual
CAD installation and METABOSS workload. Earlier public passes do not claim private
adoption, and private production code is not rewritten after each public phase.

### Phase 2 Court: The Unopened Affected Scope

Install one ordinary public catalog with two distinct Directory scopes A and B,
the same Item/Contains kinds, and lawful many-directory membership. Author all
records and memberships through installed operations. A shared item x belongs
to A and B; another item y in B has the name `taken`. The principal is lawfully
admitted for the operation and public reads in both directories. Open only A's
public prefix index. No public handle, cached session or caller-supplied scope
list for B participates in the mutation.

The installed uniqueness rule declares the prefix index as its Source scope.
Its query finds possible equal names and its own string owner checks exact
equality. An ordinary rename scoped to A changes x from `free` to `taken`.
The declared mutation lawfully writes x's name; it does not write B or y.
Native must discover both Source scopes from the actual inverse Contains paths,
prepare both candidate roots before any invariant, and invoke the existing rule
in B as well as A. Only B violates the rule. Require the rule's typed refusal
at B, unchanged committed graph/index answers, and release of staged backing.
A refusal caused by unavailable B, setup or READ denial is not this result:
the requirement explicitly admits cold reconstruction, and the fixture proves
that B's Source was acquired, its root prepared and its real rule invoked.

Use an independent authored exhaustive scan per directory for committed and
candidate expectations. A fresh rename to a distinct name commits; a subsequent
admitted public open/read in B must attach the published root, perform no new
Source/provider rebuild, and equal the scan. Reusing only A's open root,
selecting the initiating scope, reading a committed root in the candidate rule,
or treating a skipped B invocation as a pass must make this court fail.

In the same focused family, ordinary membership creation/rewiring introduces
x into a previously empty or newly created directory. The real declared
create/share operation includes the required entity/relation roles and rights;
Native's created-record correspondence supplies its full identity. A rule whose
violation exists only after that membership change must run for the new Source
scope despite its empty before-image and absent public cache. Retirement and
rewiring cover leaving scopes too. Literal IDs or a manually assembled candidate
cannot establish these outcomes. An unopened small scope is a visible cold lane;
it is not used to claim warm locality.

Pair this boundary with genuine sibling-branch, retained-basis, full-generation,
executable-version and observation/audience twins, plus cancellation of the
original request after actual root preparation. Require no matching publication,
unchanged retained committed answers and physical staged-backing release.
Separate request/failure outcomes from a domain-rule refusal. Reuse meaningful
existing controls rather than multiplying their Cartesian product. After both
providers work, the 1,000/2,000 geometry court measures the whole warm Source,
reverse-scope, provider and invariant preparation path, not just the query kernel.

unopened B. Prove both scoped rule invocations receive Native's logical Source

physical removal must not look like logical deletion or satisfy a uniqueness
rule merely by hiding rows. Public current reads must return their actual
typed suspended/unavailable denial before provider query callbacks; they cannot

under its own admitted historical basis. Cold B uses the declared cold policy

Reconstruct through the existing producer reconstruction receiver and restore

producer-continuity and required-invariant failures distinct: a fixture that

Cancel the original request after real roots/dispositions are staged and before

custody where required, and released staged backing after the last staging
holder closes. No Ready root or physical-availability change may escape a
refused, cancelled or discarded proposal. Pair this focused family with genuine
foreign/sibling basis, full-generation, definition/version and observation
controls at the owners that consume the new correspondence. Do not mechanically
duplicate the existing control portfolio. The ordinary unopened-B domain court,

## Product Decision Lock

1. Access products are derived managed resources, never authoritative truth.
2. Every strategy realizes an existing Milestone 9.10 requirement, inventory,
   budget, admitted plan, and receipt contract.
3. Search retains the installed query's identity, parameters, root, basis,
   ordering, result shape, capability, purpose, disclosure, continuation,
   recovery, and aftermath meaning.
4. Candidate production and exact refinement are distinct contracts.
5. Completeness includes positive, negative, boundary, absence, cardinality,
   authorization, disclosure, and conflict-sensitive membership.
6. Protected facts may influence internal computation only under separately
   admitted noninterference and disclosure posture.
7. Created, ready, maintaining, stale, evicted, rebuilding, disposed, and
   failed are explicit lifecycle states.
8. A realized footprint is verified from actual execution and dependency
   evidence. Caller or provider assertion grants no authority.
9. Declared authority is an upper bound. A verified footprint may narrow but
   never widen it.
10. Verified footprints feed dependency, invalidation, conflict, reuse,
    publication, commit, and Milestone 9.18 correction applicability.
11. One generic extension owns provider installation and managed state. Spatial
    and prefix algorithms live with their value/domain owners; Query and
    Relational contain no provider-specific geometry or string-search policy.
12. Candidate maintenance is staged before dependent invariants under the original
    commit owner. Preparation consumes committed-root custody; invariants consume
    candidate-root custody. Neither can substitute a matching-looking descriptor.
13. Provider installation binds exact semantic identity/version and source/query
    contracts. Portable definitions describe that meaning, not executable closures
    or serialized authority. Incompatible upgrades refuse or rebuild under a new
    admitted binding; they cannot reinterpret an older retained root.
14. Completeness and locality apply in both dependency directions: source changes
    to index state, and index changes to query observations. Whole-index invalidation
    is a conservative safety posture, never evidence of local reuse.
15. Native's sealed materialization interpretation separates logical invariant
    Source from physical candidate availability. Suspension is not logical
    deletion; a logical root is not public physical Ready. Only Native-admitted
    rematerialization and exact Source correspondence or admitted reconstruction
    can establish the resumed physical root. One atomic publication owner carries
    these meanings; Query cannot select or certify the interpretation.

## Generic Extension Contract

| Contract | Provider responsibility | Platform responsibility |
| --- | --- | --- |
| Definition | Typed source projection, query/result grammar, ordering and versioned meaning | Validate installed bindings, declared access and portable identity |
| Construction | Rebuild derived state from supplied source inputs | Supply tracked source reads and original request/allocation controls |
| Maintenance | Prepare an updated root and change evidence without mutating the previous root | Deliver complete source/lifecycle changes; isolate and bind candidate state |
| Query | Produce typed candidates and membership evidence using the admitted root | Admit the read before exposure; preserve basis, generation and disclosure |
| Dependency routing | Declare how index changes affect query predicates, including absence | Manage retained query dependencies and their incremental reverse routing |
| Disposal | Release provider-owned data within its managed lifecycle | Own retention, eviction, cancellation, reconstruction and final release |

Provider code runs through installed typed contracts with no hidden source reads,
ambient mutable state or external effects. Gathering uses the admitted tracked
reader; pure index work uses gathered values and the original checkpoint. The
framework binds every root and query observation to its actual runtime, product,
branch/incarnation, basis and definition. Domain-owned code may implement an
index; it may not maintain an unregistered private truth/freshness cache.
Returned record references are resolved by their original source owner with full
generation and admitted scope. A provider-created identifier cannot issue a read
handle, supply disclosure permission or create mutation eligibility.

Source-to-index tracking includes membership changes and indirect dependencies,
such as edge bounds depending on vertex positions. Index-to-query tracking
includes searched regions/predicates, boundaries, empty results and ordering.
The provider's typed matching contract must support local reverse routing under
the existing dependency owner; querying every retained predicate after each edit
does not meet the scale requirement. Provider descriptions are evidence inputs,
not minting rights for read, write or verified-footprint authority.

Graph truth remains authoritative. Query extends its existing managed-view owner
for roots, candidate staging and query dependencies. Relational supplies exact
source/candidate custody and commit integration; it neither imports provider
algorithms nor gains a spatial index registry. Root maintenance and invalidation
failure must refuse before publication, or enter an explicitly unavailable state
where the existing lifecycle permits that posture; correctness reads cannot use
stale or partial state. Recovery/rebuild is admitted by its existing owner and
never imports the cert-only replay facade into production.

**Owner:** Query Declaration/Installation and the existing managed-view runtime.
**Depends on:** 9.10 graph-read admission, 9.16 ordinary request/disclosure and the

**Requirements.** Declare source projection and query/result types, provider

#### Explicit Source And Scope Association

This section decides the missing authority contract; its APIs and types are
implementation destinations, not claims of availability or qualification.

`ApplicationInvariantDefinition<Schema, Rule>::managed_index_source(Index::reference())`
declares a Source-scoped invariant. The index's actual installed Source query
defines the scope entity, row projection and membership paths. The rule's existing
read/applicability contract must cover every physical entity/relation kind in
those paths and projections. Installation refuses an incomplete declaration;
it does not repair it by silently widening access. The requirement is canonical
portable definition meaning and participates in schema/program version identity.

One requirement determines the invocation scope. Additional index requirements
may share that exact Source scope type and compiled scope meaning; incompatible
scope joins refuse at installation, never become an implicit global scope or
Cartesian execution. The first prefix and box rules each use one requirement.
This constraint does not remove either provider, indirect geometry or growth
from Phase 2.

Installation produces `InstalledInvariantIndexAssociation<Schema, Rule, Index>`
by binding the real invariant, provider/version, Source query/binding, selected
schema, full physical projection, membership/predicate paths and scope pullback.
It also binds the Source root kind, scope kind, field locators/value codecs,
relation orientation, endpoint roles, nested projection dependencies, lifecycle
and absence interpretation, ordering, deduplication and result limits. Index,
scope, rule and Source names/digests describe the association; none admits reads.
Native binds its physical acquisition program to the real selected schema owner.
Query continues to own query lowering, codecs and provider mechanics. This
extends existing schema definitions and dependency postings, not a mutable
Source/index truth registry or a second evaluator.

Public `SameAdmittedScope` and `NoParameters` keep their existing meaning.
Invariant access is a separate installed Native audience; it does not acquire a
public principal, borrow a public session or turn rule kind access into Parent
READ authority. Conversely a public principal/operation grant cannot authorize
Native invariant projection. Public Source restrictions still apply: public
authorization/disclosure, no disclosure rules or capability, no Source parameters,
continuation/live/component/orbit selection or recursive managed selection.
The compiler must also prove that Source row meaning is independent of public
principal identity; admission may refuse a public read but cannot change the
canonical Source image to an audience-filtered subset.

The compiler lowers every supported Source root/projection path and guard to
finite physical forward acquisition and reverse scope/dependency paths, using
the existing path/derived-relation owners. This includes endpoints whose scalar
values determine an edge's box. Missing inverse support, ambiguous occurrence
identity, unsupported expressions or unprovable complete audience fail with
`UnsupportedInvariantSource` at installation. Required prefix and box shapes,
including endpoint dependencies, must be implemented before Phase 2 closes;
today's narrower API is not permission to omit them. There is no user callback
to supply a supposedly complete scope list or validate arbitrary raw facts.

are complementary. The qualified structural frontier alone is not a row delta
or row-read grant.

The rule's ordinary scope planner can refine its business work inside that
