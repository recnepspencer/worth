# Phase 2: exact reconstructed Source correspondence

## Boundary brief

Native owns actual suspension custody, selected physical basis, the applied
reconstruction, full-generation record identities, schema and compiled Source
support. Query owns the selected World incarnation, provider installation and
required-output lineage gates. Provider payloads are immutable derived data;
equal names, producer continuity, a manifest descriptor or a copied transaction
mode cannot authorize their reuse.

The actual materialization port already validates the selected suspension basis
and exact manifest before applying its private restore batch. Producer continuity
is computed after invariant validation, so it cannot issue Source correspondence.
Native must compare the actual applied records before Source preparation and the
first rule. Complete authoritative record equality is a conservative sufficient
proof; any mismatch must decline reuse and retain ordinary cold-policy handling.
This includes unprojected fields. Logical changes outside the manifest must also
decline reuse. MVCC and physical-residency headers are not logical record data.

The payload must come from the selected suspension root's canonical managed
image, admitted through its existing runtime/branch/registration/root/commit/
position receiver. RelationalPreparationHistory has the canonical route owner
needed to resolve the position without reading it from the image being checked.
Only an Unavailable selected association is eligible. No prior public attachment
or lookup in an older image is required. Query must still check the actual typed
provider installation. Native's unavailable committed rule READ remains refused.
Publication already mints a fresh association on Unavailable -> Available.

All proof work and temporary backing use the original execution request. A
candidate-specific proof namespace is insufficient without Native's sealed
candidate, exact program/scope and actual selected payload receiver. No execution
request is retained. Current World/producer/lineage admission remains mandatory.

Adjacent failure boundary: the Query restoration callback currently consumes its
custody before an outer final execution poll can refuse. Preserve the owned
callback result outside that wrapper so an after-callback refusal cannot panic or
lose the actual restoration outcome.

## Implementation plan

1. Add the small candidate-specific correspondence proof vocabulary in
   worth-proof, with a foreign-namespace control. In Native, project a private
   restoration origin only from real materialization custody at the actual port;
   carry it through transaction interpretation without copying custody payloads.
2. Add Native candidate_source/correspondence ownership. Under the original
   request, compare the actual reconstructed manifest and authoritative aspects
   against the retained pre-suspension source, with residency demand, checked
   accounting and cancellation checkpoints. Require unchanged schema authority,
   exact selected suspension basis and no outside-manifest logical effects.
3. Resolve the selected position through preparation history and consume the
   proof at ManagedSourceRootImage::admit_selected. Borrow the eligible canonical
   Unavailable payload for each actual compiled program/scope. Carry only the
   transient proof through Source preparation, never through committed READ.
4. Have the ordinary Query Source service consume this optional payload, check
   the real provider installation, and seal it as proposed only. Keep every
   required invariant and the normal publication path. Preserve the actual owned
   Query restoration result across the outer advancement callback.
5. Strengthen the generated Catalog public court: exact restoration performs no
   provider build/update; changed-name domain rejection remains; lawful changed
   ItemBounds falls back to a real build; original-request cancellation after
   preparation preserves custody/selection and supports retry. Add focused
   receiver controls where the new authority enters. Keep allocation accounting
   scoped to the actual journey.
6. Format dirty Rust, run focused courts then the managed-index public group,
   caps/function review, boundary-check and agent-context. Independent reviewer
   gates qa-loop, qa-tests and code-quality-qa before committing this slice.

One Cargo process at a time, default shared target/profile/features. No broad
test matrix or redundant compilation. Preserve the unrelated milestone edits.
Geometry restoration, broader lifecycle/growth courts and phases 3-6 remain
outside this slice and open in the governing milestone.

## Qualified result

The production materialization port now projects a private restoration origin
from actual suspension custody. Native compares the applied authoritative
manifest under the original request, including full identity/kind/endpoints,
canonical aspect absence/contracts/values and actual changed-record containment.
Only exact shared schema authority is admitted by this conservative proof.
Canonical history independently resolves the selected position; an unresolved
position declines reuse. The existing physical-image receiver admits the actual
program/scope and Unavailable association before lending its immutable payload.
Query binds that payload to the typed installed provider, seals it as proposed
only, and retains all existing World/lineage and required-rule gates. Publication
uses its existing fresh availability association. No older image lookup, copied
transaction mode or producer-continuity claim selects the payload.

The outer Query restoration method now retains the complete owned callback
outcome across its final control handoff. The original admitted restoration step
lives in restoration/in_phase.rs; the Query installation check is local to
source/service/correspondence.rs. Neither creates another publication path.

The generated Catalog court proves zero provider builds and updates during exact
restoration, both actual A/B rules running with unavailable committed Source,
changed-name domain rejection, and a lawful unprojected ItemBounds difference
that rebuilds both scopes. Its app-owned observation callback cancels the original
request after the first actual proposed-Source rule query. Exact Cancelled,
returned suspension custody and unchanged Native/World position survive; a fresh
reconstruction/retry succeeds. The warmed complete journey balances all owners.

The narrow Native receiver court uses a real registered publication image and
checks shared payload identity, every physical affinity axis, foreign same-name
program, absent scope and Available rejection. It claims receiver protocol only;
the public journey proves production correspondence issuance. The owner retains
its real Source lookup slot. Existing eviction correctly refuses an Unavailable
association, so no synthetic cold-eviction claim is made.

Verification passes: public managed-index group 27/27; Proof namespace 1/1;
Native receiver 1/1; dirty Rust formatting and 400-line caps on 25 files;
function review on 25 files, 21 coherent/neighboring advisories, zero scan errors;
boundary-check and agent-context. Independent qa-loop, qa-tests and
code-quality-qa review cleared the final slice. Commands used the default shared
target/profile/features and one Cargo process at a time. The unrelated milestone
draft remains exactly 311 additions/12 deletions unstaged.
