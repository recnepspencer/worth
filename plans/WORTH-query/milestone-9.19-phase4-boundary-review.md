## Verified existing authorities

- `access_strategy/coverage/` verifies actual exhaustive/checked-summary cuts,
  matched-slot bijection and exact dispositions. `CoverageFrame` compares actual
  borrowed Source/root/probe/session or Native committed/proposed audience.
  `RetainedCoverage` retains the original executable issuer and node allocation;
  it alone does not prove realized influence.
- `WorthQueryAdmittedApplicationQueryPlan` carries actual installed query,
  admitted parameters, principal, scope, product/basis, graph session, governance
  and selected issued access. Managed selection purpose and lease issuance
  already check exact original Parent/Source/session correspondence.
- `ManagedSourceRead` is currently one whole-Source Native observation. Its key
  is obligation+scope, its equality is same Native association, and its ordinary
  currentness calls `managed_index_source_is_current`. Thus two probes of one
  Parent can share the same current fact key only because their current meaning
  is the entire Source. Selective meaning cannot inherit that key unchanged.
- `ManagedSourceDependencies` retains that observation even for empty outputs.
  Legacy completed Sources retain every original row and result-set owner.
  Public observed selection equality and descriptor identity currently preserve
  this conservative dependency meaning and actual coverage.
- `PersistentSourceRows` owns an immutable ordered map of genuine full-generation
  entity occurrences to shared `Entry` allocations. Warm updates clone the map,
  replace only actual changed entries and preserve the owner identity. Each Entry
  contains the actual projected Source tree and dependency posting set, including
  nested endpoints. This supplies a conservative way to recognize unchanged
  influencing row bodies without comparing application DTOs or scanning Source.
- The same installed adapter runs complete candidate traversal and optional exact
  refinement. A new comparer must reuse that path, its genuine controls and issuer;
  it must not interpret prefix/geometry meaning in generic Query.
- Native `observe_managed_index_source` already observes exact physical material
  at a genuine selected snapshot under original execution. It grants no READ.
  Existing Native source observation affinity is runtime+branch+registration,
  distinct from record revision and snapshot. Sharing a payload through ForkExact
  is not evidence that a sibling branch observation belongs to the original cell.

## Candidate direction and unresolved facts

The simplest candidate uses the actual installed verifier to capture original
admitted plan/probe/complete coverage and candidate-row custody, then reuses the
same adapter at an exact target Native Source image. Reverified negative coverage
and unchanged genuine candidate Entry bodies can preserve observations across
irrelevant Source edits. This avoids a full Source scan and per-result query.
Keeping all candidate bodies, including exact rejects, is a lawful conservative
influence superset; returned exact rows alone are insufficient.

This direction still needs independent boundary review and exact placement of
the captured→verified transition. The legality witness belongs in worth-proof;
owned rows, execution/control, installed verifier and observation loans belong
in Query Execution. A separately created issuer must open no installed receiver.
Missing/incomplete/mismatched evidence must stay conservative or refuse, never
become an empty verified footprint.

Verification at commit must produce a fresh genuine Native observation of the
checked target and feed the existing atomic pin/preflight; comparison followed
by an unpinned commit is a race. Fresh request/read/effect admission stays with
its existing owner. Capture may retain passive correspondence and funded raw
parameters, but no old grant or reusable read-session decision.

The alternative is private observation custody in the existing inverse predicate
axis. That would have to share its one routing tree and publication metadata,
preserve Native-only/pending/World/correction semantics and never introduce a
second subscription/conflict engine. It is not selected merely because watch
routing already exists. Determine which verified boundary produces the smallest
honest initial vertical slice before writing the implementation plan.

## Independent boundary resolution

The independent reviewer confirms the targeted forward-adapter direction for the
first currentness/atomic-commit slice. Private retained consistency verification
is distinct from public READ: existing fact verification and demand owners already
consume admitted captured bodies at a genuine target under the original request,
without a new public Query principal session. The new private audience must bind
the actual retained-verification owner/extent; no counterfeit Public session or
Native invariant loan may stand in for it. Return only a typed comparison and
actual target-pin custody, never public rows/availability/candidates.

Capture the original genuine completed cut and ALL candidate entries, including
exact rejects. Reuse that already admitted material; do not rerun original
callbacks just to reconstruct its fact. Only the target complete traversal runs
again. Actual immutable Entry sharing is a sufficient conservative equality
proof; lack of sharing is not proof of changed values and can require reread or
a later admitted semantic fallback. Full-generation keys, actual Native cell
identity, program/scope/install and complete parameters/mode remain independent
checks. Fork payload sharing cannot substitute for Native cell affinity.

The installed predicate_profile compiler verifies complete Source/Parent physical
projection correspondence, tracked root predicates (including enabled), and
projected ordering inputs. This can conservatively retain all candidate-row
support, while the full target cut covers absence. It does not enable arbitrary
Parent shapes or erase ordinary non-managed root/field/effect facts.

Admitted parameters already have an owner-issued canonical identity and funded
raw bindings. Use that existing meaning for a selective fact key and still
retain/check the actual bindings and issuer; no second parameter codec or
runtime counter identity is needed. Complete canonical encoding and duplicate
merge must preserve each obligation.

An additional verified consumer boundary remains for the later reuse slice:
ManagedSourceDependencies currently hashes the whole Native Source revision into
observed Source identity. Even a successful selective fact comparison cannot by
itself make a newly captured demand identity match the retained output's old
identity. Do not claim irrelevant-edit output reuse until semantic identity and
source comparison are carried through that actual ordinary demand path. The first
slice may prove currentness and real atomic expectation commit without claiming
that wider reuse/correction/selected-membership completion.
