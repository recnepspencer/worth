# Phase 3: exact managed Source structure

## Boundary review

The current node seal admits empty/nonempty posture and an available root. It
cannot distinguish a tree containing every genuine Source occurrence from one
that duplicates a slot and omits another. Candidate slots prove positive
membership only. Phase 3 needs an exact root decomposition before its traversal
verifier can discharge searched and pruned obligations.

Native's Source service already couples the actual before rows and provider node
backing in one retained ManagedSourceRoot. It checks the installed association,
uses Native's complete changed-occurrence delta, and seals the proposed pair at
the same receiver. Public Ready similarly owns its completed Source and nodes.
Keep this owner; do not add an image stamp or issuer. Source slots retain their
owner and full-generation occurrence identity across maintained edits.

Provider Node remains opaque pure material. A declared binary Source-tree
profile exposes its actual own Source slot and up to two child coordinates.
Prefix AVL and box BVH use this profile; unsupported Opaque providers retain
their explicit conservative posture. This profile is a structural contract,
not complete query coverage, exact refinement, READ or narrowing authority.

Use the existing ExecutionOrderedMap for grant-correct persistent metadata.
Query owns three maps: node-to-checked-region, child-to-unique-parent, and
Source-slot-to-unique-node. Nodes remain in their existing immutable pages.
The private physical writer records every edited coordinate. No provider list
or count substitutes for that actual dirty set.

At cold construction, every source-bearing region must name a genuine slot,
every slot is unique and their total equals the actual Source cardinality.
Every live node is described, every nonroot has exactly one parent, the root
has none, and cycles are refused. These facts establish one connected tree and
the exact Source universe, including the genuinely empty Source.

Warm edits carry that invariant. Remove all old dirty-node edges/slots before
adding replacements; reject duplicate edges even when their parent agrees.
Validate new child coordinates against actual live pages, refuse an incoming
edge to a removed node, require exactly live-nodes-minus-one parent keys, and
check cycles through new edges' parent chains. Unchanged valid keys plus these
checks establish connectivity by induction. Apply the complete Native delta as
remove-before/add-after: a stable slot updated in place must remain present.
Removed-only slots must be absent, added slots present, and the resulting slot
count must equal the actual after Source. Never scan a warm Source/node roster.

All preparation, allocation and provider decomposition remain outside Native
publication locks and use the original request/control. Existing Native
before/proposed custody supplies exact frame authority; the metadata never
escapes its actual provider/root pair as an independent witness.

## Implementation

1. Add portable Source-structure vocabulary in Foundational and expose it through
   Decl. Bind Structure to the typed Index definition, canonical identity and
   archive codec. Definition v1 remains explicitly Opaque; v2 carries Structure.
   Unknown versions/profiles refuse before payload interpretation. Installation
   retains its actual typed descriptor equality, so transported profiles cannot
   replace installed meaning.
2. Add the Host provider decomposition surface and typed structural refusals.
   For example, a prefix adapter declares BinarySourceTree and returns its pure
   node's genuine slot plus left/right coordinates. Query contains no prefix,
   box or comparator policy.
3. Add a private source_structure owner alongside managed node backing, with
   separate files for region representation, paid map edits, cold admission and
   incremental transitions. Keep provider-specific extraction as a thin generic
   shell; graph/map validation is a concrete core compiled once. Retain the
   checked descriptors for the later coverage traversal to consume directly.
4. Track actual dirty node coordinates in the existing isolated writer. Cold
   extraction visits its initialized page span; warm extraction visits only
   recorded edits. Admit the fixed-width edit scratch and map/path allocations
   through the original SDK, and drop scratch before retaining the new root.
5. Qualify structure after provider build/update and before Ready/root retention.
   Structural denial, cancellation or allocation refusal drops the staged root
   and preserves its predecessor. Port the real prefix and BVH adapters, including
   maintained adapters, to the declared profile. Do not add a second root or
   subscription registry.
