# Source-scope cascade retirement

D1044 accepts source-scope ownership as an explicit installed producer contract.
This supersedes the D1043 custody block; ordinary references remain non-owning.

## Boundary review

Query owns producer declarations, source-specific query/scope eligibility,
installed producer identity and the exact authored correction source/inverse role.
Native owns genuine source birth, recorded publication membership, closure,
current payload/relations, atomic publication, canonical history and restoration.
worth-proof owns the legality seals. Neither a submitted roster nor a reference
can establish membership in the cascade. Non-opted-in producers retain the
existing single-publication path.

The principal risk is incomplete retirement that looks complete because only
submitted targets were searched. Native must select every current publication
from bounded ancestry before computing the source-scope closure. Another risk is
collapsing several routes into a synthetic producer; each selected publication
must retain its own canonical membership, provenance and predecessor. Ordinary
authored source birth remains separate from producer membership.

Restoration preserves the existing authored inverse's Create posture: it issues
fresh native generations rather than reviving an old full-generation identity.
Every restored publication must correspond to its retired original, with complete
member correspondence, original payload and correctly remapped relation endpoints.
The source logical key remains governed by the existing authored correction
binding. No partial restore may publish. No durable installation depends on the
old format: increment the canonical/durable protocol and reject old formats;
there is no migration or interpretation of old bytes as the new meaning.

## D1054 correction boundary

The adversarial sequence is retiring a child publication through the legacy door,
then retiring its parent after history no longer connects the live leaf. The owner
must close every publication retirement door, not rely on Query supplying an anchor.
An opted-in publication is rejected by legacy authored retirement before completeness
can hide the ownership subject; installation independently rejects a retained-custody
bypass. Producer Preserve remains lawful for leaf replacement, but cannot delete a
member that scopes a live owned publication, or leave its own source retired. Restore
must establish each restored publication's live source in the same candidate.
Ordinary unbound Native commits retain their existing CascadeDeletePolicy semantics;
they are not authored-publication custody admission.

Native owns these gates and their typed publication/owner subjects. Query keeps the
existing authored correction binding as its anchor source. New courts must run real
Create -> producer demand -> retire_created -> restore_retired through a program,
observe literal three/seven-record rosters, and drive the anchorless refusal route.
Native refusal courts also cover partial anchorless rosters, intermediate source
retirement, producer replacement with a live dependent, missing-owner restoration,
and the two-step orphan probe. Existing independent and leaf-replacement behavior
remains protected. Re-run the full Native suite, touched Query crates, repository
gates, and the same owner courts after a clean cherry-pick onto 84488468bb.

Query now asks Native to refuse owned Retire targets on that path while leaving
independent candidates unbound. Native refuses a Preserve succession whose whole
new roster is Retire, in addition to source-severing replacement. Both have courts.

(`retire_created`) from reversal of the declared Retire (`restore_retired`);
reversing a correction receipt would instead request existing reapplication.

The no-opt-in installation remains a constant-time no-op. A court first prepares
