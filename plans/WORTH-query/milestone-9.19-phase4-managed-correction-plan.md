# Query9.19 Phase4: conservative managed correction plan

Read the [boundary review](milestone-9.19-phase4-managed-correction-boundary-review.md)
first. Both documents precede Rust changes.

## Result and scope

Qualified maintained managed facts can participate in recorded correction when
all conservative canonical Source-scope candidates have authentic performed
cancellation and strict original/complete target support agrees. Unqualified
captures and unavailable history still refuse. Ordinary correction remains in
the same owner path. No public historical query mode or exact authored relevance
claim is added; same-scope false positives remain a Phase 4 follow-on.

## Module responsibilities and steps

1. Native observation history child: original control poll, actual selected runtime
   correspondence and delegation to the existing Source roster issuer using
   private program/scope. No program/hash reconstruction or READ issuance.
2. Query retained influence trait/concrete owner + ManagedSourceRead: expose the
   actual observation's selector only with admitted retained realized proof;
   preserve an explicit unsupported result for missing/unqualified influence.
3. restored_support/overlap: retain an original-funded managed selector array
   alongside unchanged ordinary keys. Count and copy both under original controls;
   every captured fact must project or refuse. Do not silently skip unsupported
   facts. All-managed facts may skip the empty ordinary cursor; the pre-existing
   truly empty-selection refusal remains.
4. restored_support/history: extract the existing canonical collection loop into
   one cohesive owner, feed ordinary and managed cursors into its same Occurrences
   map, preserve paid map operations, real canonical ownership and typed causes.
   Keep page width a physical granule, not a history ceiling. Cancellation remains
   unchanged, followed by the existing strict-original/paired-target comparison.
   No candidate relevance filter in this conservative posture.
5. Existing maintained Catalog correction modules: declare genuine conventional
   recorded note/name operations, bounded field pre-images and dispatch through
   Contribution::visit_correction. Use actual SourceCompletion actions and writer
   handlers; no new world/SDK setup or fake correction witness. Declare all meaning
   once in this existing root and add only its handlers/actions to Program.
6. Existing external managed court: real source receipts and actual reverse/close
   journeys. Cover populated/empty managed input, canonical ordinary+managed union,
   real cancel/restore success, raw restoration refusal, uncancelled authored no-op
   and transient entrant refusal, and explicitly conservative same-scope refusal.
   Verify actual final note/name values and no publication on rejected preparation.
7. Update capability and correction docs, milestone status and actual evidence;
   obtain unconditional independent qa-loop, qa-tests and code-quality-qa gates,
   then commit this vertical slice.
