# Phase 3: explicit complete Source-tree membership

## Boundary review

SourceTree admission now establishes one actual connected binary decomposition
and a bijection to the exact Source occurrences. The ordinary adapter still
hands provider.query a candidate writer. That callback can omit a valid subtree
without a structural error: Source completeness does not establish searched
predicate coverage. Both public selection leases and Native invariant reads
consume that same adapter; fix that authority point once.

The existing installed managed-index definition binds the genuine Source,
provider/version, probe codec and Parent descriptors. Installed access meaning
also retains the actual Parent graph, ordering and result shape. Public and
maintained selection leases retain their admitted sessions and exact Source/root
pair. These remain the admission, frame, principal and audience owners. Native
invariant reads retain their real committed/proposed Source loan and original
work budget. No new image stamp, issuer, registry or callback subscription is
needed for complete traversal.

The safe first traversal contract is explicitly exhaustive. Query visits every
retained checked region and calls a pure provider predicate on each actual
Source row. A provider receives neither a candidate writer nor the remaining
tree in this callback. It cannot stop traversal successfully, prune a region or
substitute a slot. Probe validation precedes traversal, including on an empty
Source; a bad probe must not become an empty success. All callback, decoding,
allocation and cancellation failures retain their real first cause and discard
the partial candidates.

This is complete candidate membership for the installed provider predicate.
It is not exact domain contact, a checked pruning contract, a retained predicate
posting or legal narrowed influence. Existing complete conservative Source
dependencies remain authoritative. Explicit exhaustive work is proportional
to the entire Source and cannot support a locality claim. Existing candidate
providers remain unchanged unless they opt into this declared contract; the
maintained large geometry provider keeps its existing candidate profile until
checked summary traversal is available.

Portable membership meaning belongs in Foundational's planned managed_access.rs.
Declaration authors it, canonical identity/archive transport it and Installation
already compares the entire definition to its typed recipe. Framework coverage
orchestration belongs at primary_graph/access_strategy/coverage. SourceTree
remains the sole checked graph owner, exposing only controlled read access to
its retained descriptors/parents. The completed adapter still returns the
existing private slots under its purpose completion. No new legality witness
is minted; worth-proof's future receiver must consume actual qualified traversal
and refinement evidence before any narrowing can occur.

## Implementation plan

1. Declare portable Candidates and ExhaustiveSourceTree membership modes, with
   Candidates the default. Definition v3 binds membership; v1/v2 keep their exact
   old wire and canonical meaning and decode as Candidates. Refuse an exhaustive
   profile without BinarySourceTree, an old-version claim or an unknown wire tag
   before Source payload decoding. Test canonical identity and actual typed
   installation so a transported tag cannot replace installed meaning.
2. Add pure provider validate_probe and matches_source(row, probe, control)
   callbacks. The latter defaults to a typed MembershipUnavailable refusal.
   Query owns the complete exhaustive path; legacy query remains the existing
   explicitly conservative candidate path. No provider-kind switch is added.
3. Implement a concrete stackless traversal of the retained regions/parents.
   Enter each region once, visit every genuine Source slot, and finish only
   after all checked regions and Source contributions were actually visited.
   Use paid ordered-map lookups and O(1) scratch. Route the generic row/predicate
   callback through a thin closure, so the graph walk compiles once.
4. Select the installed membership path in the common typed adapter. Validate
   the probe before allocation/navigation; invoke matches_source only on the
   framework-selected genuine row; emit its slot only when the predicate holds.
   Finish the candidate array only after traversal and Source/decoder checks.
   Public, maintained and invariant consumers share this same cutover.
5. Opt the real prefix and small public box adapters into exhaustive membership.
   Their pure UTF-8 and closed-box owners still decide matching. Keep callback
   observations as actual probe validations and remove their displaced ordinary
   provider-controlled query mechanics. The legacy default refuses, so an
   accidental fallback fails the ordinary positive membership oracles. Add an
   interrupted matching court with a lawful twin.

## Evidence and limits

Use the existing installation/archive courts for v1/v2 preservation, v3 profile
round trips, impossible combinations and literal unknown-tag rejection. Use the
existing public journeys' independent ordinary Source oracles for prefix ties,
Unicode, nonmatches, empty results, box boundary equality and Parent ordering.
The warm prefix courts exercise actual insertion, retirement and stable-slot
rename through the common invariant adapter. Add a focused interruption during
actual row matching: no partial result, exact typed cause, retained Ready root,
and a fresh lawful request must still agree with the independent oracle.

Run the production execution check, those focused archive/installation targets,
then the existing public managed family excluding the large geometry growth
court. Reuse current compiled-document drift, formatting, boundary/context,
dirty caps and function scrutiny. Do not rebuild the full Query cfg(test) owner
or rerun the 16-minute predecessor workload for an unchanged geometry profile.
The independent reviewer gates all three QA skills before a slice commit.

Phase 3 remains unfinished: checked summary pruning/locality, retained reverse
predicate routing, read/registration interference, tracked exact refinement and
continuation/disclosure qualification are subsequent required work. Phase 4's
verified narrowing and later adoption remain separate obligations.
