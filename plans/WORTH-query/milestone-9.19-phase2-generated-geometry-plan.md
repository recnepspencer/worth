# Phase 2: generated endpoint Source lifecycle

## Boundary brief

The existing Catalog owns Directory/Vertex/Edge identity and actual ContainsEdge,
Starts and Ends relations. Its installed BoxIndex projects both canonical endpoint
regions, and ProbeContact judges closed integer enclosures at the fixed probe.
This slice uses those same owners; it adds no numerical algorithm, tolerance,
exact segment predicate, topology store or Source authority. Coordinates retain
the existing declared unit/frame and canonical codec. The independent oracle is
the literal authored edge roster and closed integer comparisons.

Real required-output publication must create the Edge and BOTH Vertices in one
producer operation, with all three entity roles declared and both Directory
memberships plus endpoint relations. Native's actual manifest and Query's real
reconstruction receiver then cover endpoint payloads, rather than an edge linked
to independently authored vertices. Native-authored B edges supply the independent
counterexample: moving the reconstructed endpoint to 50 causes a third enclosure
in B while A remains lawful. B is unopened publicly, not claimed cold.

The shared Catalog already has a real Directory Source binding and fixed prefix
output. Geometry can reuse that admitted Directory query, with its own source
action, producer, conditional field readiness and fixed output root. Program
outputs accept a tuple of roots; existing actions keep their own delivery root.
The geometry producer consumes the actual source directory and creates a fixed
0-to-10 endpoint pair. Its dedicated request action writes its own source note.
Readiness is installed through the existing typed field contract; no separate
readiness-behavior qualification is inferred from installation.

Native already owns logical suspension reads and exact restoration correspondence.
The counterpart must prove those production paths on endpoint projections: both
actual scope rules retain their logical rows through suspension; current public
reads refuse; an invalid reconstructed endpoint reaches B's real rule; exact
restoration reuses backing without build/update and still judges both scopes.

The original request can be cancelled by an app-owned observer after the first
actual geometry rule query during suspension. At that point Source preparation
has run, but no publication has moved. The result must preserve exact Cancelled,
unchanged Native/World selection and available public reads; a fresh selected
suspension must retry. This is pre-cutover cancellation evidence, not a claim of
late-success or pending-recovery execution.

The suspension outer advancement wrapper currently returns its owned result
through a final poll that can discard it. Capture the complete outcome outside
that wrapper, including ProductUnpublished custody. Reuse the ordinary in-phase
suspension owner. A Query control-stop projection must preserve the original
Native preparation error; share Native-to-Query execution classification with
restoration rather than add a second classification authority.

   producer settlement and all three declared output roles. Populate independent

   all actual entity roles and both retained Directory memberships.
