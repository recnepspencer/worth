## Existing owners and constraints

Native's coupled_assembly owns the applied state, full-generation route and
writer admission. Query supplies separately admitted real handlers. The source
and every writer share one actual candidate; there is one final invariant
judgment and one World publication. Existing managed cleanup retains original
causes and runs outside locks. Those properties must remain.

The current seams cannot simply be relabelled:

- coupled_assembly/part.rs::require_unseen_route refuses a repeated route.
  participant_admission.rs independently enforces the same fence. Removing
  either check alone would grant a second writer without continuation custody.
- coupled_assembly/prepared_route.rs returns a descriptive index, not writer
  authority. Query's execution/coupled_source.rs currently reuses that index.
- a new applied round cannot masquerade as a committed Native predecessor.
  Existing prior-output reads must receive a distinct owner-issued applied
  predecessor, tied to this candidate and this route.
- required_output_origin/members.rs requires coverage of every prior live
  member. Publishing only the last completion's live roles would omit original
  members that the first round retired. Combining all submitted roles would
  falsely retain transaction-local facts created and deleted before publish.
- each CoupledPublicationPart retains one applied input. The canonical origin
  has one before basis; LivePublicationInputs and predecessor_publication_input
  expose one exact input. Neither the first nor last input represents all
  inputs of several genuine executions. A navigation/checkpoint origin is not
  a substitute.
- ComputedSlot transports genuine computation; it does not decide publication.
  post_authorization/preparation.rs currently sends every completed handler to
  compare-and-commit. Bitwise input reuse is a different proof and cannot
  stand in for executed effect equality.

No publication/ownership implementation, SHA or content-commitment owner is in
scope for edits. Current roster and position writers remain independent and
must check the same final candidate. Work visits touched rows/routes/rounds;
there is no model scan or canonical-history fallback.
