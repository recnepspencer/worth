# 9.19 Phase 2: explicit refusing Source initialization

## Boundary brief

Current Native activation precedes ordinary seeds and all rules remain active.
Cold::Refuse intentionally covers new scopes; missing-before and unavailable-before
are different. The bootstrap is a move-only unpublished owner; Native delivers
the actual before/after scoped views. Source installation already binds the real
provider, Program and canonical preparation/publication path. A new explicit
construction admission belongs above that path, not in a Native posture boolean.

The governing milestone now fixes an explicit next-seed-batch initialization lane.
Proof matching belongs to worth-proof; session/Drop/funding belong to Query's actual
resource owner. The bootstrap holds the issuer, services hold matching authority,
and the registry holds only a weak active session. Exact admitted basis plus a
single exclusive seed-commit closure binds the attempt. Original funding and
strong basis/session custody must leave runtime guards before final Drop. No
initialization witness enters roots or recovery. Public rebuild remains separate.

## Plan

1. Add matching initialization proof types and a funded Source authority/issuer
   pair during existing Source compilation. Move the issuer into bootstrap;
   service authority remains with its actual compiled resource. Use the existing
   typed installed service and its Program as the index selector.
2. Add bootstrap.initialize_managed_index::<I>(phase), collecting exact installed
   Program selections with owned original-request funding. Consume pending plans
   at each seed attempt, including failure/empty-batch paths. Refuse recovered
   publication. Empty pending initialization yields EmptyBootstrap.
3. After activation, begin a resource-owned guard around exactly one seed commit,
   using that transaction's exact AdmittedBranchBasis. Keep its strong carrier
   outside the Native runtime closure; registry lookup is weak. Validate proof,
   selected Program and exact basis before initial preparation.
4. Add initial Source preparation beside ordinary preparation, validating the
   actual available new-scope before/after loan, propagating all unavailable
   errors, and reusing cold construction/sealing. Existing/live/retired Sources
   keep ordinary policy. Keep normal pre-first-rule and publication cutover.
5. Add a fixed public Refuse prefix catalog reusing existing query/provider/
   mutation/directory modules. Share the existing maintained rule evaluator, with
   separate fixed declaration meaning. Test omitted/explicit/empty initialization,
   actual bootstrap rule execution, warm edit, evicted-B refusal, public refill,
   retry, new-scope refusal after bootstrap, and exact final-owner allocation.
   No runtime policy changes or injected roots. Add type/compile-fail evidence
   that the initializer is absent from installed runtime.
6. Run consumer typecheck first, then the scoped new court and impacted existing
   managed-index group. Run focused proof/session owner controls only where they
   add distinct authority evidence. No concurrent Cargo, feature/profile/env
   variants, or unrelated package testing. Run mandatory boundary/context, format,
   dirty caps/functions and independent QA gate; commit this slice.

and session custody lives with Query. The registry's active session is weak and
matches the exact Native admission used by its one exclusive seed transaction.
The outer guard releases basis and backing after runtime locks on all outcomes.
The actual ordinary materializer, pre-rule preparation and compound publication
remain the sole canonical updater. Initial-program activation still precedes
seeds, and the fixed Refuse declaration never changes its cold posture.

Bootstrap denials now retain the existing canonical Native validation failure;
borrowed Source/custom/law accessors preserve typed original causes. The new
court checks exact InitialState/Publication stages, RootUnavailable and custom
Violation rather than accepting arbitrary errors. It also checks omitted and
foreign selection, empty and unrelated-attempt consumption, seed rules, warm
maintenance, evicted shared-scope refusal, explicit refill, identical retry and
post-bootstrap new-scope refusal. Its isolated journey balances all final owners.
