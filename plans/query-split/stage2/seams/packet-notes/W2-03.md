# W2-03: producer output evaluation evidence (family E, step 2)

Design: `contracts.md` Family E, steps 2 and 3. Seams: `application_output_demand` →
`application_contribution` (evaluation part) and `causal_inspection` → `application_contribution`.
Edited without compiling; the integrator's wave pass compiles it. W2-02 (step 1, the bridge refusal
translators) runs in parallel on the same seam and merges first.

## What moved

`unit_move.py` moved four items whole, with their impls, from
`application_contribution::producer::output_evaluation` into a new child
`application_output_demand::settlement::output_evaluation`:

- `WorthQueryProducerEvaluationIneligibility` (public; the facade name is unchanged: `facade.rs`
  `causal_inspection::application_inspection` and `causal_inspection::mod.rs` now re-export it
  from the new path);
- `ProducerOutputEvaluation`, `ProducerOutputEvaluationState`, `ComparedProducerOutput`
  (all `pub(in crate::domain_computation::primary_graph)`, as before).

The re-exports inside the old owner (`application_contribution/mod.rs`, `producer.rs`) are removed;
there is no shim. Every user now names the new path: `readiness_delivery.rs`,
`registry/ready_backing.rs`, `settlement/observation.rs`, causal inspection's
`connection/evaluation.rs` and its `extended_tests.rs`.

What stays in contribution: `InstalledOutputComparison::evaluate` (the producer's comparison, which
constructs the lowered evidence), `NativeOutputBasis`, `OutputEvaluationVisit`, `native::prepare`,
`installation::install`. They name output demand's types downward.

## The trait

`ProducerOutputFieldScope`, owned by `application_output_demand::settlement::output_evaluation`,
visibility `pub(in crate::domain_computation::primary_graph)`:

```rust
fn locus(&self) -> &ApplicationFieldBindingLocus;
fn contract_revision(&self) -> AspectContractRevision;
fn meaning(&self) -> [u8; 32];
```

Implemented for `InstalledProducerOutputEquivalence` in
`application_contribution/producer/output_equivalence_contract.rs`. The evidence's two scope
fields (`ProducerOutputEvaluation::field`, `ComparedProducerOutput::scope`) are
`Arc<dyn ProducerOutputFieldScope + Send + Sync>`; the accessors `field()`, `contract_revision()`
and `field_meaning()` read through it. The design's grep holds: contribution reads nothing of the
evidence beyond `visit.evaluation` and `visit.compared_now`, and causal inspection reads only
`field()`, `role()`, `contract_revision()`, `field_meaning()`, `state` and the comparison's public
fields. No downcast.

Because the fields are private to output demand now, the evidence gained two constructors,
`ProducerOutputEvaluation::new(field, role, state, memory)` and
`ComparedProducerOutput::new(scope, role, entity, kind, revision, performed_basis, comparison)`,
both `pub(in crate::domain_computation::primary_graph)`. `evaluate` calls them with
`Arc::clone(&self.field) as Arc<dyn ProducerOutputFieldScope + Send + Sync>` (the codebase's form
for an `Arc` unsizing cast).

## Generics

None added, none kept. `dyn`, accessors only, as designed.

## Behaviour to watch in the compile pass

- The two scope fields are fat pointers now (16 bytes instead of 8 each), so
  `Layout::new::<ProducerOutputEvaluation>()`, which `evaluate` reserves as retained memory, grows
  by up to 16 bytes per evaluation (enum layout decides the exact figure). A test pinning that
  reservation exactly would move.
- `native.rs` reaches the refusal through `use super::*` no longer; it imports
  `WorthQueryProducerEvaluationIneligibility as Refusal` from the new path. Variants and matches are
  unchanged byte for byte.

## Step 3: `PendingProducerPublication` not moved

The design moves it by hand only "if its impls name only output demand and lower types". They do
not: `close` and `close_prior` take `&dyn ApplicationContributionHost<S>`, `ContinuationState` holds
`InstalledProducerEdition` and installation's `WorthQueryRecoveredProgramOutputSource`, and the
recovery path is `state_mut().progress::<Schema, Binding>(...)`, generic over the producer binding.
The fallback, "route through the checkpoint host method", names a method that does not exist:
`OutputDemandHost` has no checkpoint method, and the reference is the field type of
`WorthQueryOutputCheckpoint::PublicationPending { owner }`, which the registry stores by value.
Lowering it behind a trait object would need contribution to take the concrete owner back out of
the checkpoint (`checkpoint_delivery/unpublished.rs`, `demand/read_close.rs`), which is the downcast
the design rules out; making the checkpoint generic would spread a type parameter through the
whole registry. Left as is (1 reference, `registry/checkpoint.rs`); it needs an owner ruling.

## One reference added to an existing seam

`ProducerOutputEvaluationState::CaptureUnavailable` names `application_attempt::OutputFieldCaptureFailure`.
The design calls the attempt "below both"; under the host order it is not, so the move adds one
reference to the existing `application_output_demand` → `application_attempt` seam (46 → 47 in the
host-order run). The edge is not new. `OutputFieldCaptureFailure` is held by
`retained_decision_facts::StoreDenial`, which is the decision-fact store vocabulary W2-08 lowers;
it goes down with that family.
