# Restoration header corruption courts

The ordinary courts in
`worth-court-relational-certification::relational::restoration_header` protect
public issue [#78](https://github.com/recnepspencer/worth/issues/78). They exercise
`validate_output_origins` through ordinary historical inverse admission, rather
than calling a replacement validator or parsing a debug error.

Each court independently creates three authored anchors and three owned output
publications, including native relations, through real schema installation,
transaction validation, publication binding, preparation, compare-and-publish,
and settlement. It retires all three sources together, restores their exact
recorded publication rosters with fresh generations, then retires the restored
sources. Preparing that final retirement's inverse walks the actual recorded
restoration and cascade headers.

The lawful twin admits before corruption. A sealed, receiver-scoped history door
changes one descriptive header fact in a copied recorded envelope. The court
then requires `TransactionCommitError::Publication`, the exact
`AuthoredRetirementRefusal::CorruptPublication`, its affected entity, and the
specific header refusal detail. The exact branch observation must remain
unchanged: inverse custody is refused before a candidate can publish. The door
restores the original history residency and catalog using `Drop` when history
has not advanced, and the lawful inverse admits again afterward. It records
both the next commit ID and the catalog's latest commit at installation. If
either changes, it keeps the advanced history intact and panics with the
before/after coordinates; during an existing unwind it prints those coordinates
and aborts. A separate court commits inside the scope and requires that loud
failure while observing the retained catalog commit and entity truth.

The door accepts a closed corruption enum, not arbitrary replacement history.
Its header copying excludes the envelope's diagnostics and authority-bearing
fields. It creates no validation proof. Boundary-check restricts the door and
its corruption vocabulary to the owner and the exact leaf court callers in
`control-callers.txt`. The existing work and missing-entity doors return only
counts or strings, while the general ledger-tampering door is unit-test-only.
Neither provides typed historical inverse admission from these leaf courts.

## Independent cert mapping

The independent #74 cert's section 2a maps these checks to the current owner.
The new courts cover the following mapped corruption refusals:

| Cert checks | Court behavior |
| --- | --- |
| 2 | Revived anchor; empty restoration publication roster |
| 3–4 | Missing anchor mapping; absent anchor Create patch |
| 5 | Repeated co-anchor; missing co-anchor mapping |
| 6 | Repeated old entity generation; revived native generation |
| 7 | Repeated relation generation; absent relation Create patch |
| 8 | Incomplete native origin membership |
| 9 | Unowned publication; missing exact member mapping |
| 11 | Missing recorded relation inverse |
| 13 | Repeated original route; repeated output member |
| 14 | Foreign source; cyclic source ownership |
| 15–16 | Unowned relation; unowned entity |

Check 1 is work metering, covered by the existing cost court, rather than a
corruption refusal. Checks 10 and 12 are defensive `usize::checked_add` count
overflow guards. A small lawfully admitted envelope cannot overflow either
count through one fact corruption. These courts do not counterfeit vector
lengths or add synthetic count controls to claim coverage of those guards.

The authored cascade courts separately protect the grouped anchor, anchor
uniqueness, owned publication, origin membership, repeated route, foreign source,
and cyclic source refusals. Header failures are attributed to the first recorded
publication's source, including a source deliberately corrupted by a source
court; an empty publication roster uses the admission source fallback.

## Mutations

The campaign removes each refusal class or its relevant predicate, runs its
exact court once, restores the file bytes, and verifies SHA-256 equality. The
independent cert's duplicate-generation collapse mutation inserts both entity
keys unconditionally and checks only `old == new`. The duplicate-generation
court changes one old output generation while preserving all new IDs and
cardinalities, so count or missing-membership checks cannot replace the lost
uniqueness check.

Commands, timings, exits, exact mutation patches, failed court output and full
restoration hashes belong to the external lane evidence directory, not source
control. The validator's production decisions remain unchanged; the compiled
additions are sealed court support only.
