# Composed output measurement

This temporary diagnostic increment measures two reproduced output-tree stops:
required-wave preparation admission and an exact consumed upstream settlement
missing from managed publication custody. It delivers measurements, not a fix.

The first journey is an installed parent producer with two genuinely discovered
child occurrences. Initial settlement and settlement after an authored upstream
edit both use the ordinary complete program-output API. The receiving host
retains its existing resource profile and source code throughout measurement.

## Boundary findings

Required-wave selection and reselection fund positioned native snapshots,
discontinuity observation and shared Query basis preparation through the same
carried admission. Preparation bytes are cumulative across that advance. The
typed preparation subject maps multiple non-work stops; it does not identify the
failed charge by itself.

Managed prerequisite selection joins the actual consumed settlement identity to
its exact posting. Missing live postings can only use the existing verified
checkpoint-root posture. This increment preserves that guard and the separate
pending-readiness cue. Posting publication, repointing and removal remain owned
by the existing registry and native lifecycle paths.

## Measurement implementation

Add one private `primary_graph/composed_output_diagnostics` module. It retains a
fixed ring of 128 descriptive posting events, containing complete fixed-width
settlement identities and numeric demand descriptors; it holds no Arc, runtime
lease, source query or executable authority. New events overwrite the oldest
event. A diagnostic dump reports overflow and prints at most 128 events.
The receiving process opts in with `WORTH_QUERY_COMPOSED_DIAGNOSTICS=1`; the
diagnostic branch emits and stores no events without that environment setting.

Instrument only posting fill, repoint and removal, and exact missing prerequisite
joins. Each missing join records its fixed publication path (ordinary performed
commit or stable-cutoff publication). A process emits at most four failure dumps.
Successful events do not print. No field values, authored keys, producer names,
source payloads or external repository metadata enter the trace.

On denied preparation admission, report the unchanged original native stop,
charged bytes, requested charge, required bytes and installed maximum. Include
at most 24 lines and 4 KiB of backtrace text through a fixed output buffer, without
building an unbounded formatted string. Capture occurs only after denial and
outside the meter lock. Diagnostic storage/output is temporary observational
overhead, not evidence of ordinary execution cost.
The required-wave denial mapper also reports its unchanged original native stop,
because its preparation subject includes non-memory alignment stops. It shares
the same process dump bound.

Do not change admission totals, denial mapping, budgets, source currentness,
registry membership, settlement custody, publication effects or recovery. No new
issuer, wire format, public facade or operational identity is introduced.

3. Commit locally for reviewed ordinary Git dependency receiving. The coordinator

   receiving host's local logs; the public tree contains only generic code/plan.
4. Compare the denied charge and identity read/posting/removal timeline. Establish
   a genuine public RED fixture at the measured seam before choosing a fix.
5. Remove every diagnostic code hunk before releasing a behavioral repair. Retain
   exact stale, foreign, missing-posting, tight-budget and deferred/drop controls.

Warm reuse, older checkpoint repair, restored retirement authority, broad
currentness changes and resource-profile increases are outside this increment.

## Local validation

Independent source review accepted the corrected central opt-in guard and the
bounded diagnostic diff for measurement only. Focused execution-owner controls
passed: carried admission (one), missing upstream with diagnostics enabled and
disabled (one each), and settlement posting work (four). The admission trace
reported the original 4095-byte total plus a 2-byte request against 4096 bytes,
and reached the original charge caller within 14 backtrace lines. The disabled
missing-upstream run emitted no diagnostic output; successful posting controls
also remained silent.

These checks used Rust 1.94 with the test/execution crate at optimization level
zero and debug information disabled; inherited dependency overrides remained at
optimization level two. Formatting, dirty Rust line caps, context and whitespace
checks passed. Boundary checking reproduced the same six existing UI source
reachability findings as the baseline, with no diagnostic-scope finding.
Receiving-host measurements and any behavioral repair remain separate gates.

## Bounded attribution refinement

Recoverable byte denials can consume all four dumps before the final
required-wave mapper or a missing prerequisite is reached. Reserve one dump for
byte denial, one for the required-wave mapper, and two for missing prerequisites,
while preserving the four-dump process maximum and the same ring/trace bounds.
The private diagnostic module alone owns these observational counters.

The removal event currently identifies the shared obligation helper, which has
several cleanup and lifecycle callers. Propagate `track_caller` through both
release wrappers, their inner helper and the matching-release helper to expose
the original immediate caller in the existing event. Do not add new events or
change release conditions, custody or accounting. Verify the revised source with
independent review, focused existing admission/prerequisite/posting controls and
the same guards before a local diagnostic-only commit. Current integration-cut
phase attribution must come from its own completed receiving trace; an earlier
whole-tree test failure does not establish which settlement phase failed.

Refinement source review accepted the fixed per-class counters and caller
propagation. The same seven focused test runs passed, including zero diagnostic
output when disabled and during successful posting controls. Formatting, dirty
line caps, context and whitespace checks passed. The combined byte/mapper/missing
quota sequence remains a receiving-runtime measurement gate, rather than a claim
derived from these separate focused processes.
