# Composite correction and owner-effect custody

This public 9.18 Phase 2 slice covers simultaneous Relational and Signal
definition successors and their interrupted publication. Phases 3–4 stay held.

## Boundary findings

The adversarial condition is a prepared correction whose first owner has moved
while cancellation or a competing publication prevents World from publishing.
Readers must retain one complete selected World; actual owner movement must
remain recoverable and must never become a reported rollback or success.

World already owns this progression. Query's ordinary application publication
in `provider/application_attempt_state/commit_preparation/relational_commit/
commit_execution/product_publication.rs` consumes a conditional-definition
change with the Relational candidate in one `prepare_combined_candidate`.
Bridge admits the exact selected Signal predecessor and prepares the definition
successor. The existing World conditional-definition publication retains the
candidate, activation and both owner results through its recovery custody.
The existing application idempotency reservation protects that same publication.

The native effect builder already accepts the move-only
`WorthQueryAdmittedApplicationConditionalDefinition`. Its issuer binds runtime,
schema and exact product observation; `advance_conditional_definition` rejects a
foreign observation and a duplicate change. The temporal host court exercises
real combined application publication through this low-level public path.

The recorded correction entry prepares the installed inverse's ordinary
`OperationHandler` and commits that candidate with native causal source evidence.
Its `CandidateWriter` currently cannot carry a conditional-definition change,
and `DecisionReader` cannot prepare one against its admitted product. Thus the
ordinary recorded-correction handler handoff is incomplete even though combined
publication below it exists. A second correction publication implementation,
caller-invented component identity, or restoration of derived Signal values
would duplicate or violate the existing authority.

An authored definition correction can derive its replacement parameters from
the existing retained Relational pre-image and construct a new owner definition
successor. It must not switch the target back to an old Signal basis. The handler
must prepare against its already-admitted exact product, not perform a new
current-head lookup. Native decision reuse must classify this context access so
an opaque owner permit cannot become reusable computation output.

## Existing evidence and precise remaining proof

Reuse the accepted source-field, required-output and correction recovery courts.
Their historical projection, causal receipt and input custody are unchanged by
this slice. Existing World courts already cover:

- `operation_control/combined_race.rs`: real Relational movement loses to a
  Signal-only publication before Signal is called; exact old World remains
  readable and the loser retains one actual owner effect.
- `operation_control/races.rs`: real Signal movement loses the final CAS to a
  Relational contender; concurrent readers observe only complete old/new pairs.
- `operation_control/faults.rs`: Signal-only cancellation immediately before and
  after canonical movement has truthful no-effect/unpublished outcomes.
- `operation_control/settlement.rs`: pending durable Relational settlement
  prevents Signal execution, retains custody, and settles without republishing.
- Native `definition_publication/recovery.rs`: activation denial/unwind retains
  the actual Bridge candidate and Signal successor without World visibility.

Missing focused World evidence is cancellation in a **combined** attempt at the
Signal owner boundary: before Signal movement, Relational has already moved;
after Signal movement, both owners have moved. Both must retain the exact
partial results while World readers still see the complete predecessor. This
must use real owner pauses and observations, not a callback that merely returns
an invented partial result. A lawful combined twin establishes the candidate
and both owner operations actually succeed when uninterrupted.

## Composite replay identity boundary

The real composite correction publishes both components successfully, but its
exact replay returns `IdempotencyIntentDrift` (native court log
`q918-phase2-query-composite-native3.log`). Commit preparation binds the admitted
conditional-definition identity into the idempotency record. Fresh replay
admission intentionally skips the handler and therefore has no newly admitted
definition. Full completed-binding equality then compares the original identity
with `None`. Re-running the handler would mint a new successor and would not
prove replay of the original publication.

The completed replay selector already validates current disclosure, exact
correction intent, inverse binding and retained encoded input. Carry the
original conditional-definition identity through the existing opaque correction
intent from this validated record. Bind only that descriptive definition field
when constructing replay idempotency; preserve fresh operation, principal,
scope, precondition and governed-input admission, and preserve full equality
and drift refusal. First-use intent carries no definition and the ordinary
handler remains its only definition issuer. Implement in `correction_source`
intent/replay and expose a crate-scoped idempotency definition getter.

The native composite court is the failing regression: require exact original
Relational commit, World commit, Signal publication, generation and causal
source, then deliver the original performed correction and observe its actual
conditional wake. Reuse the existing stale-target and same-head controls.
