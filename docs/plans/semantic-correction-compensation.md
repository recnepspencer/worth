# Typed compensation through the ordinary correction entry

This public 9.18 Phase 2 slice follows the committed fixed-root correction and
recovery work. Phases 3–4 remain held. It establishes executable compensation;
Bank accounting/process adoption and the remaining Phase 2 obligations stay open.

## Boundary review

`ApplicationCorrectionBinding` currently describes only recorded inversion:
`preimage_demand` is mandatory, contribution expansion calls `recorded_inverse`,
the contract constructor hardcodes RecordedInverse, installation's association
resolver rejects Compensation, and native derivation requires a retained pre-image.
Native compatibility also unconditionally compares the original source's complete
rebased after-image facts. Those checks correctly protect exact restoration.

The existing correction-mechanism owner already distinguishes RecordedInverse
and Compensation. Compensation rejects ExactPriorTruth and carries a business
postcondition. Its provider read-scope correctly requests no recorded pre-image.
The original authority binding retains the actual installed aftermath contract;
that retained contract, rather than a newly inferred posture, must select native
material and applicability rules.

Shared truth remains the installed source/corrective mutation association,
historical occurrence and input, disclosed original subject, exact ancestry and
target, current installed program interpretation, and fresh ordinary admission.
Compensation identifies the actual original performed effect from that historical
evidence. Its separately installed handler reads the current target and admits a
new forward operation satisfying the declared business postcondition. It must not
restore a captured balance or accidentally inherit exact-after-image equality.
Recorded inversion keeps its complete existing fact comparison and missing-
pre-image refusal. External-owner reconciliation remains a distinct authority
posture and is not admitted by this runtime-alone compensation slice.

Bank has an additional verified material boundary. SendMoney input does not name
the Journal actually created. MoneyMovementResult contains that identity, while
the source mutation presently declares NoApplicationMutationOutputs. The later
Bank adopter must bind its actual created Journal output and project the declared
identity field from native immutable committed material after fresh disclosure.
Neither a caller-supplied Journal identifier nor derivation from a client key
can stand in for that witness. This slice does not claim that adopter is complete.

## Intended contract and topology

The one correction binding explicitly declares its mechanism. The declaration
owner derives the corrective operation slot from the binding's concrete mutation
type; no operation name becomes executable dispatch. Contribution expansion uses
the same generic correction installer for both supported mechanisms.

Native derivation supplies a closed, read-only material variant selected from the
source occurrence's retained installed mechanism: RecordedInverse with its real
pre-image view, or Compensation without a manufactured pre-image. The domain
derives its corrective intent from original input plus that variant. Existing
fresh disclosure, ordinary admission, canonical command identity, candidate
publication and output/recovery owners continue unchanged.

The existing portable/canonical/archive contract already carries mechanism and
the typed source/action association. Extend its current installation validation
to resolve compensation's concrete action and legal postcondition. Do not add an
association registry, permissive string lookup, duplicate correction entry or
generic snapshot access. Corrective association naming must describe both
mechanisms accurately where the changed public contract exposes it.

## Ordered implementation

1. Generalize the existing correction declaration to explicit mechanism and
   mechanism-specific derivation material. Derive recorded-inverse capture and
   compensating operation slots from the same concrete binding. Update the two
   actual recorded binding implementations and their usage guidance together.
2. Extend existing native association installation validation to admit runtime-
   alone Compensation only when its actual operation, handler, input, disclosure
   and business postcondition resolve. Preserve all recorded-inverse validation,
   portable round trips and external-owner restrictions.
3. Select material and eligibility from the original occurrence's retained
   installed aftermath axes. Recorded inversion still compares complete rebased
   source facts and requires the actual pre-image. Compensation retains exact
   historical/program association and lets fresh corrective admission govern
   current eligibility. A different installed mechanism never silently falls
   through another branch.
4. Add a numeric source credit and separate debit action through ordinary native
   handlers and installed actions. Publish +30 from 100, then +7 on the same
   balance; correct the first occurrence to reach 107. Verify Compensatable
   posture, genuine source linkage, preserved unrelated work and exact replay
   without another handler invocation. Add current-authority refusal with a
   lawful twin. No dummy pre-image, fake receipt, caller-derived source identity
   or test-only behavior enters the production path.
5. Run focused declaration/installation and native consumer evidence. Reuse
   adequate unchanged recorded-inverse/output/adoption evidence, with a single
   grouped native run where the shared fixture changes. Batch affected metadata,
   formatting, dirty line-cap/composition checks and constitutional enforcement.
   Use unoptimized incremental compilation, unrestricted jobs and 64 MiB stacks.
6. Existing independent reviewers inspect the actual mechanism boundary and
   evidence. Update the consumer guide/capability entry with the concrete API.
   Commit this coherent slice while keeping all unproved Phase 2 work open.

## Required negative evidence

Installation must refuse an association whose compensation slot or disclosure
names another actual installed binding and must preserve Compensation's rejection
of ExactPriorTruth. A missing recorded pre-image remains a recorded-inverse
refusal. A changed target/current authority must still stop before new effects.
Exact retries retain the original key/intent and source occurrence; no second
compensating action or new input substitution is allowed.
