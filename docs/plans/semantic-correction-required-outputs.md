## Boundary review

The existing ordinary required-output entrance knows Program, Root and Binding.
It derives demand before publication, reserves source custody before effects,
retains the performed observation, and classifies native performed, unpublished,
blocked and retention-failure outcomes. Its fixed-root preparation starts the
ordinary demand under a fresh request. The output owner retains source/root
identity and continuation interests.

The erased correction request currently commits only ordinary actions and refuses
output sources. Removing that refusal would bypass custody. The inspected roster
has descriptive root membership but no executable erased demand/start adapter.
The first entrance therefore retains concrete correction, program and root types.
This extends the existing correction and output owners. The Phase 2 contract
requires declared-closure reconciliation through existing demand and settlement;
it does not require automatic erased root selection. The checked typed entrance
satisfies that fixed-root obligation without a TypeId-based executable adapter.

Native correction derivation already validates the exact installed association,
freshly discloses source material, compares semantic dependencies, and seals the
actual inverse input, principal, scope and exact target. The checked typed output
entrance may allow required delivery only after validating selected root/source
membership and the exact inverse action's installed fixed-delivery root. Independent
membership of a source and a root cannot establish their association. Ordinary
correction retains its refusal.

Recovery has a concrete identity edge: ordinary fresh recovery admission computes
ordinary idempotency, whereas correction binds a canonical correction command.
The original unpublished output-source owner must carry the sealed correction
context and extend the freshly admitted binding before equality checks and native
resolution. Current authority/input/scope checks stay in place.

The fresh-key native court proved that unconditional rebinding accepted a
different caller key (`Ok(Performed)`). Keep the original inverse key identity
beside the correction intent on the existing unpublished source owner, captured
before canonical command rebinding. Only an exact fresh inverse key may acquire
that command binding. A different key retains its fresh binding and the existing
source validation refuses it. This also preserves a correction's declared inverse
key transformation without asking recovery to infer it.

An equivalent retry returns exact committed status while the caller retains its
existing move-only output obligation. A copied receipt cannot replace that owner.
Publication-pending, owner-effects-unpublished, performed-source/output-pending and
completed output remain distinct.

The genuine append-failure journey reproduced a nested command-lock deadlock.
The preserved process dump places the worker in correction lane entry from the
ordinary idempotency resolver, called by managed unpublished recovery while its
original command guard is still held. Recovery already releases its branch guard
there. Release its command guard at the same handoff, after the recovered session
has installed pending/completed evidence and the unpublished checkout has finished.
Keep both lane owners alive across ordinary resolver readmission. This preserves
the command-before-branch order and leaves no interval without provider custody.

After that handoff was repaired, the same native recovery reached receipt
projection and exposed a second loss: equivalent receipt construction discarded
the provider's sealed aftermath relation. Recovered receipts must carry that
relation from their actual committed provider record. An equivalent retry with

The genuine unpublished journey asserts the recovered correction's original
source before settling its retained output owner.

### Consumer recovery handoff

The native court's explicit construction of the known numeric inverse is useful
for adversarial input/key refusals, but cannot be the general consumer contract:
an application caller need not know the protected pre-image-derived inverse.
Publication already owns `ApplicationOwnedMutationIdentities` with the actual
shared encoded input and transformed inverse key. Retain that existing carrier
on the original unpublished/retention-failure owner when a recorded correction
returns one. Ordinary source owners carry no recorded input. Fresh-request
methods on these owners reconstruct only the ordinary request admission from
the retained carrier and delegate to the existing recovery/promotion/retention
paths. They neither rerun inverse derivation nor grant authority. Every denial
preserves the original owner; no public input getter or alternate registry is
introduced. The native court must use this entrance for successful recovery and
promotion while retaining explicit wrong-input/key tests for the lower entrance.

1. Parameterize native correction compatibility/derivation by delivery selection
   inside its existing owner. A typed required-root entrance validates installed
   source/root membership and retains that exact root in the sealed preparation.
   The ordinary action entrance accepts only source completion.
2. Extend the existing selected required-output commit spine with correction
   causality. Verify inverse/input/root seals, bind the canonical command, and
   forward RecordedReverse through the existing native source publication with
   output observation retained. Reserve and promote custody in the existing path.

   between ordinary and typed output preparation. Keep public delivery wrappers
   small. The typed publish path derives demand from the actual captured inverse
   input before effects and feeds the actual single commit into the existing
   performed-outcome classifier. Do not manufacture preparation after a commit.
4. Carry correction context on existing unpublished output-source custody. Fresh
   recovery extends only correction key/intent after ordinary admission, before
   source validation or idempotency/recovery work.
   End both existing recovery coordination guards before entering the ordinary
   resolver again, after its existing publication handoff. Use the reproduced
   genuine recovery journey to protect this boundary; a test wall-clock guard
   also turns a mutex stall into a terminal test failure.
5. Extend the numeric public model with an independently calculable required
   output. Save a real source, preserve a disjoint edit, reverse it and reconcile
   the output through its ordinary producer. Refuse output start under a foreign
   request while returning the original owner; retry through a fresh lawful
   request. Replay the correction while delivery is pending and verify the same
   source receipt and unchanged inverse/publication counts. Preserve genuine
   unpublished recovery with its original owner and current authorization.
6. Document the typed path and returned custody where ordinary correction is
   introduced. Keep the guide aligned with executable public examples.
