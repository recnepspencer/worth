# Semantic correction through the ordinary application entry

**Status:** Completed and covered by certified Phase 1 acceptance.
The [9.18 specification](../../plans/WORTH-query/milestone-9.18.md)
owns current milestone progress.

This plan records the completed ordinary-entry slice's historical boundary review,
implementation order and intermediate verification notes. The full milestone is
public-only; private consumer adoption does not gate closure.

## Boundary review

The adversarial case is correction of an ancestor after a disjoint target edit:
the correction must preserve that edit, append to the target's current composite
head, retain its exact Signal definition basis, and require current authority.
An overlapping edit must refuse before effects. A copied receipt locates history;
it cannot authorize effects or supply otherwise unavailable original meaning.

Existing authoritative boundaries are reusable:

- World owns exact retained ancestry, branch incarnation, head comparison and
  composite component publication. Query's `product_operation/history.rs`
  already selects an owner-issued retained World history entry. That API is
  branch-local: a fork starts reference generation zero, so its history page
  stops at the fork root. Correction needs a separate owner-issued selection
  of an inherited ancestor, without fabricating a target branch generation.
  Follow that target's parent chain through exact catalog lookups under the
  original request's interruption and explicit selection controls; retain the
  selected occurrence and authentic target observation. There is no catalog
  scan or reconstructed history fallback. A stopped selection remains distinct
  from a proved non-ancestor or unavailable source.
- The provider captures demanded pre-images from the admitted decision facts
  intersected with the validated candidate's mutation footprint, before commit.
  Its committed-application record retains that pre-image, canonical patch and
  exact composite publication independently of the caller's receipt.
- The original governed input and installed aftermath currently reside in the
  receipt's `WorthQueryApplicationCommitAuthorityBinding`. Equivalent receipt
  construction recreates that binding from the retry admission. These facts
  must instead be co-retained with the actual performed occurrence.
- Ordinary Publication stages typed identities, freshly authorizes the selected
  branch, resolves idempotency, executes the installed handler and publishes
  through the existing program/World owner. Its preparation and required-output
  custody remain the downstream handoff.
- Aftermath declaration and installation resolve descriptive inverse slots and
  pre-image coverage. An executable binding must additionally tie the source and
  inverse operation, handler, codec, source expectations and output contract.
  The installed handler/declaration pipeline owns that binding.
- Historical disclosure and inverse execution are distinct current admissions.
  The binding names an existing application query whose installed meaning governs
  the retained input and pre-images. Capture its canonical parameters during the
  original admitted operation, alongside the original native scope selector and
  full subject identity. Freshly resolve and execute that query on the target;
  require the original subject's actual root/row before invoking domain derivation.
  Neither a successful unrelated read nor permission to repeat the old action
  supplies historical disclosure. Existing query admission owns this decision.

The provisional recovery-handle undo handoff does not prove this boundary. It
cannot be promoted into ordinary correction authority. No correction history
registry, scheduler or second World publication owner is introduced.

## Implementation order

1. Preserve original operation meaning with provider-owned committed evidence.
   Capture it while the original admission is present, carry it through the
   existing attempt/publication state machine, and recover it from that record.
   Share the existing immutable native input carrier so its backend and final
   allocation custody survive admission and receipt disposal.
   Retain the actual source program record and existing interpretation custody
   after the native occurrence-program gate verifies an ordinary action or required
   output source. A declared correction cannot commit without that capture. This
   preserves original program meaning independently of the target's active program.
   Exercise disposal/response-loss and equivalent resolution at the owner.
2. Extend aftermath declaration and installed binding resolution with the typed
   inverse association. Resolve executable meaning through existing installed
   handlers; validate source/input/pre-image/output compatibility before effects.
   One contribution clause derives native membership and Self-bound typed dispatch.
   Conventional original inputs are fallibly frozen before handler execution;
   execution and historical evidence share the exact native input carrier.
   Extend that original capture with the declared disclosure query's canonical
   parameters and the scope selector retained by native entity resolution.
   Preserve the association through the existing package archive codec.
3. Add owner-backed exact occurrence selection and correction admission under
   `application_aftermath/correction/{selection,admission,planning,reversal}`.
   Re-resolve the receipt's exact publication through retained ancestry and
   retained provider evidence. Fresh authorization and target program support
   determine legality; historical approval never substitutes for them.
   Validate the dispatched source/inverse types against the exact installed
   association even for manually implemented schemas. Run the declared disclosure
   query on the exact target before exposing input or pre-image to application
   callbacks; compare the full original subject identity so a reused logical key
   cannot select a replacement. A filtered/empty query cannot authorize history.
   Perform disclosure before returning a public selection and repeat it immediately
   before inverse derivation. Raw receipt input/pre-image access remains owner-internal;
   provisional reversal refusals read the installed disclosure contract, so absent
   retry capture metadata cannot weaken the requirement.
   Exact selection is issued beside the existing primary-graph product operation,
   where provider evidence and World observations are accessible. Query execution
   keeps root inspection native: share the ordinary one-shot completion owner
   while reading actual disclosed root identities without an application projector.
4. Prepare one inverse candidate against the exact target head and publish it
   through existing ordinary Relational/World component machinery. Retain the
   target Signal basis. Bind the canonical correction cause and branch-local
   consumed edge to the publication; preserve typed no-effect, unpublished and
   mandatory custody outcomes. The plan's mutation shape admits create/retire,
   while their correspondence bindings remain Phase 2.
   Plain requests resolve the same sealed selected-program owner as typed program
   requests. Co-retain the already installed native program records on the existing
   program-support owner during assembly; share their installed allocations and
   action/output-root inventories. Both resolvers use one issuer that verifies the
   selected runtime, active native revision and retained support. Revision text or
   descriptive roster membership alone cannot construct a commit owner.
5. Expose `request(...).on_branch(branch).corrections()` in the existing host
   application-entry facade. Selection is opaque; preparation is consumed once.
   Add the compiled `application_correction` example and grouped
   `application_graph/correction` scenarios through the public audience facades.
6. Review the actual correction and evidence with the existing independent
   source and QA reviewers. Update consumer guidance and capability discovery.
   Certify and close only Phase 1, then merge the complete public change to
   `master` after fetching and reconciling any intervening public updates.

## Acceptance and verification

The Phase 1 public integration court observes corrected authored source values,
preserved disjoint edits, exact component bases and the new composite parent.
Required-output reconciliation and derived readback extend this court in Phase 2;
an unsupported delivery refuses before effects during Phase 1.
Its independent expected values also distinguish overlapping refusal, copied
versus foreign selection, revoked current capability and repeat idempotency.
Native owner evidence covers original capture and exact retained lookup.
Compile-negative cases with lawful counterparts cover forged selection,
inspection-as-permit, preparation reuse and retained-read mutation.

Discover grouped target names and run metadata checks before code generation.
Batch necessary native tests into the existing Query cache, with incremental
development/test profiles, unrestricted Cargo CPU jobs and a 64 MiB Rust stack.
Reuse unchanged publication, recovery and execution evidence where adequate.
Run scoped formatting, dirty Rust line caps and composition review, followed by
the required boundary-check and generated agent-context checks. Do not clean
caches or change compiler flags between checks without a demonstrated need.

The historical Phase 1 acceptance gate required the complete public path,
adversarial evidence, repository gates and independent review. No private build
or edits were part of this plan.

### Replay and semantic compatibility boundary

First-use correction checks the original operation's semantic dependencies at
the exact target snapshot. The existing decision-fact owner separates application
meaning from principal and authorization facts; its source-output subset alone
does not necessarily cover every original handler read. Capture the complete
semantic subset at that owner and rebase own writes through the existing native
postcondition machinery. Failed or missing coverage refuses, and original actor
permissions never become compatibility requirements.

Replay uses the completed-evidence owner's existing branch/incarnation/key index.
A private, non-disclosing probe compares the native inverse binding and immutable
correction intent before recovering the actual performed inverse input. That
input is freshly admitted and compared through ordinary idempotency resolution;
it is retained even when the inverse is not itself correctable. Pending or
unpublished publication cannot resume before fresh authority. The immutable
intent names the original occurrence and installed correction association, never
the mutable target head. First-use compatibility and inverse derivation are
skipped only for an authenticated, exact already-performed intent.

Canonical key encoding has its own populated phase in the existing mutation
identity owner: `ApplicationEncodedMutationKey` owns the actual binding-specific
key and its single encoding. After a private evidence probe, it joins either the
newly captured inverse input or the exact co-retained encoded input to produce
the ordinary owning mutation identities. No caller supplies a digest as proof.
The original input owner retains the full `ApplicationEncodedInput` carrier,
sharing its existing native backend and canonical capture rather than encoding
a recovered value again.

Replay scope selection uses the existing binding-specific
`ApplicationMutationInputScope` contract, as native producers already do. A
private input adapter forwards the actual encoded value and that declared scope
into ordinary fresh binding admission. It never asks the domain to derive an
inverse again, reconstructs an old permission, or treats the original domain
intent envelope as a current execution grant. Corrective input is retained for
retry even when the installed inverse is not itself reversible.

### Exact publication and causal linkage

Extend the existing aftermath commit lane. It already fixes the prepared parent
and disables ordinary automatic basis readmission. Its current causal `parent`
conflates the historical operation with the new child's actual parent; recorded
correction separates these meanings. The prepared context retains exact target
observation, ancestry protection, performed source evidence and original program
material through existing pending/unpublished attempt custody.

The existing co-committed causal row carries explicit source World owner/ordinal
and source Relational branch/commit, alongside the actual expected target parent.
The canonical reader validates the complete role-specific payload. The child's
single ancestry parent remains the expected target parent; historical source
linkage is causal metadata. Its command key derives from immutable correction
intent, excluding the selected preparation head. The native action gate binds
the inverse binding and current actor before effects. Fork branch identity must
come from actual admitted target ownership rather than the source receipt.

The inherited fork root's parent receipt still names the original commit's
branch. Carry the writing target branch separately, taken from the admitted
target basis. Compare the new child branch with that writing branch, and its
single parent commit with the observed target parent's commit ID.

Correction command lookup must ultimately span actions and target branches, as
the Bank court requires. The existing inverse-binding key namespace and product
affinity cannot establish that contract. Extend the current idempotency owner's
lookup scope and existing coordination owner: ordinary operations keep product
affinity, while correction commands share one application/schema/caller-domain
key namespace. Source, inverse action, target incarnation and actual inverse
input belong to bound intent. Pending, unpublished and completed entries carry
the same correction lookup identity; no parallel custody registry is introduced.

The prepared context seals the native captured inverse input identity and the
scope resolved from the derived intent under the current inverse principal.
The action gate compares the actual handler input and admitted scope with that
seal. Capture occurs after derivation and the captured carrier is reused by
admission, handler execution, publication and subsequent retry.

Correction lookup uses the canonical application/schema/caller/wire-key
namespace in the existing completed, pending and unpublished stores. The causal
row uses that immutable command key. The coordinator acquires command lanes
before branch lanes, sorting distinct keys for batch inspection. Branch close
selects a pending command before locking and rechecks it under coordination;
a changed selection refuses before settlement. Pending-to-completed publication
keeps command coordination across the evidence insertion and pending-slot
removal.

The native correction-disclosure court is an exact registered caller of
Installation's sealed certification-query constructor. It uses the existing
authorization-world fixture to distinguish a real nonempty related-root read
from disclosure of the original root, and to test projector noninterference.
The construction permission remains confined to that Execution test file.
Production inverse capture forwards Publication's existing access value into
the native capture owner; Execution does not issue that access for itself.
