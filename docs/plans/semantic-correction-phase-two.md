## Boundary review

The performed occurrence retains its actual installed source program and a native
interpretation pin. The selected target resolves its current program through the
existing activation record. Correction presently requires pointer identity between
those records, so an ordinary adoption to equivalent installed meaning prevents
correction even when the inverse remains exactly supported.

Installation already owns semantic comparison through adoption requirements and
complete action comparison through the installed action inventory. Those descriptive
results cannot authorize effects. Query must freshly disclose the original subject,
compare its semantic dependencies, admit the inverse under current authority, and
publish against the exact selected target. World continues to own currentness and
Signal retains the target's exact definition basis.

A binding alone cannot choose among several feature occurrences. Resolve a unique
original inverse action, then resolve that exact declaration in the target inventory.
Missing, ambiguous and changed actions refuse. Until a broader compatibility recipe
is implemented, changed program meaning returns its actual owner-computed support
requirements. A matching revision string or digest is insufficient.

The prepared correction must retain the target interpretation as well as the source
material, using the existing support lifecycle. No additional program table, cache,
publication path or authorization token is needed.

The real adoption court exposed an additional handoff defect before inverse
derivation: adoption prepares authorization/workflow indexes but omits the
ordinary query predicate indexes. Fresh disclosure then has no generation at
the adopted head and the native owner returns `ColdReconstructionRequired`
with zero records read. Ordinary reads correctly refuse population reconstruction.
Adoption must carry the installed primary index inventory through its existing
candidate-owned incremental maintenance, just as ordinary source publication
does. This preserves authentic predecessors and performs no read-side fallback.

## Implementation

1. Extend the existing installed action inventory with unique binding resolution.
   Use its existing complete-declaration resolver for the target occurrence.
2. Replace correction's allocation-identity test with existing installed program
   comparison. Preserve typed comparison, action-resolution and changed-meaning
   refusals. Keep required-output refusal until its own custody path is integrated.
3. Carry the current program interpretation into the prepared source context;
   preserve original input seals, current admission, semantic dependency checks,
   exact target comparison and ordinary World publication.
   Include installed primary indexes in adoption's existing incremental candidate
   preparation. Reuse its exact predecessor snapshot and payer; retain legitimate
   missing-predecessor and resource refusals. The observed failing disclosure is
   the regression case, alongside the native index-maintenance evidence.
4. Extend the existing numeric public example with a real adoption capability and
   rostered successor programs. Execute A → B adoption through the public request
   owner, then reverse A's occurrence under B. Read independently expected fields,
   current program and retained Signal posture. A changed inverse declaration must
   refuse, and adoption after correction preparation must make publication stale.
5. Document this supported path in the consumer correction guide and correct the
   engineering spec's outdated prepare/publish example to match the real API.
